* Runtime ownership

MRR =runtime/= owns the Rust transport, bounded worker lifecycle, original typed
MRR adapters and Data publication orchestration. POO contains no Rust runtime
crate or compatibility alias. It supplies Scheme semantic modules, C ABI and
Python Library. Data supplies Backend/Protocols and durable transactions.

MRR CI consumes the immutable POO dependency declared in its =gerbil.pkg=.
It builds the native Library from that dependency and owns Rust/Python comparison
and native-to-Data physical acceptance. POO CI qualifies its Scheme core, C ABI
and Python Library; it neither checks out MRR nor pins the MRR runtime.
Historical build-freeze receipts retain their original commits and paths.

* Current delivery plan

The [[file:next-delivery-plan-v1.org][2026-10-05 delivery audit]] records the updated ASCENT revision,
current owner pins and ordered acceptance gates. Earlier implementation and
qualification sections below retain their historical source/artifact scope.

* Fixed Scheme v1 protocol constraint

The current implementation keeps Scheme transport and semantic ABI versions at
v1. JSON removal changes the representation, not the protocol version. C
exports, Scheme descriptors, Python/Rust consumers, MRR transport and Backend
records must agree on v1. Earlier v2 qualification sections below are historical
evidence and do not qualify the fixed-v1 artifacts. No v2 or JSON fallback is
part of the current consumer path. Source currentness through the Data commit
remains a separate atomicity gate.

* Current implementation and remaining authority gates

The current delivery authority is [[file:next-delivery-plan-v1.org][the fixed-v1 delivery ledger]].
Agentic AI Lab owns Temporal interpretation, proof replay, immutable evidence history,
current applicability and IFC semantics. MRR owns original typed identities,
query/result admission and production orchestration. MRR Data owns physical
execution, Backend/Protocols, conditional transactions and recovery.

The consumer graph pins MRR =ffde2798a5246a61f4d6f0e66d7f05156e55e38f=
and Data =513d67812c45875bfa991b5b0032f37cffcb5998=. Data declares that same
MRR revision. Both Cargo locks are generated by Cargo; the executable graph
checker also reads resolved original Data source. MRR source cut
=937f9a51d8b56aa054a1cb8f30499e75aa09275a= changes formal tooling and documents
relative to this runtime owner. Selecting it would require updating Data's own
manifest first, rather than loading two MRR identity types.

Implemented bounded slices include original GQL physical result exchange and
correction, acyclic alternative-support evaluation, positive ASCENT proof
replay, original MRR rule/catalog and Derivation correspondence, exact source
leaf binding, and host-registered proof/current catalog/journal/policy checks.
Dedicated ABI v1 controls retain proof inputs; ordinary read-only queries cannot
replace current state, policy or the observed clock. Source authentication,
complete support inventories and effect authorization are not inferred.

MRR's Library qualification uses one native artifact for its original Rust
evidence and installed Python Library replay. Success qualifies the named
bounded lifecycle only. Physical execution remains a separate executable gate
in MRR, using the same artifact and Data's authoritative port. Historical
receipts retain their original pins.

C SQLite publication currently admits only an initial root. Replacement,
tombstone, durable current-state fences and crash recovery must compose the
MRR Data authoritative commit port. Two independently passing stores do not
establish one atomic publication. Recursive/absence profiles and a general
native-to-Quint trace correspondence remain separate work.

* Audited seams and necessary corrections

| Source seam at the pinned MRR/MRR Data revisions | Actual guarantee | Design consequence |
|------------------------------------------------+------------------+--------------------|
| =mrr-property-source/src/source_query.rs= | Original GQL source compilation, catalog/snapshot binding and candidate admission | Preserve the original compilation and bound query throughout execution |
| =meta-relational-reasoning/src/query_result/api.rs= | Typed row/identity/budget admission and original transport re-admission | A valid result digest alone proves neither backend execution nor exhaustive answers |
| =mrr-revision/src/{api,snapshot}.rs= | Canonical external revision identities, one generation and no conflicting logical source in a snapshot | A host correspondence binds temporal cuts to these identities; no clock/generation coercion |
| =mrr-lineage/src/api.rs= | Acyclic graph admission and reverse reachability over supplied edges | Impact schedules reevaluation; it cannot decide whether alternative support survives |
| =mrr-agentic-ai-context/src/state.rs= | Context elements with declared dependencies and temporal FactId references | Export applicability evidence as explicit dependencies and check it at consumption |

The current MRR projection document preserves native GenerationId separately
from Temporal host generation, and records snapshot/cut correspondence as a
missing verification. Keep those identities distinct. A receipt digest alone
cannot authenticate source execution or establish a causal cut.

MRR lineage =Derivation::new= checks output metadata and support identifiers;
it does not replay a rule over independently authenticated supporting facts.
=impact= traverses predecessors of every supplied edge kind and returns fields
named =directly_invalidated= and =transitively_invalidated=. At the Temporal
boundary these mean /candidate reevaluation frontier/. It neither encodes
AND/OR support semantics nor proves the graph contains every dependency.
=why_one_witness= selects one outgoing edge at each visited node; it cannot be
used as a complete conjunctive premise certificate. Preserve owner scope.

* One loop, two immutable histories

#+begin_example
source revisions -> Temporal evidence journal -> as-of cut + projection
                         |                              |
                         |                         MRR snapshot/catalog
                         |                              |
                         |                 MRR Data physical query/execution
                         |                              |
                         +<- checked correspondence <- original typed result
                         |                 + derivation/coverage evidence
                  Temporal proof replay
                         |
               immutable conclusion revision
                         |
               MRR conclusion/receipt facts -> query / Context references
                         |
              current-applicability check -> authorized runtime publication

source/policy/clock/coverage change -> dirty frontier -> reevaluate -> new revision
#+end_example

Keep historical facts and receipts immutable. Distinguish an as-of query from
a current query explicitly. An old statement that a classification held at a
past cut can remain true while its eligibility for a current decision is stale.
A tombstone withdraws a current conclusion; it does not erase history.

Prevent self-authentication in the return path. Export a conclusion as a claim
with its proof and dependencies, never relabel it as an independent observation.
A query consuming that claim retains its original premise closure. Reimporting
the same claim under a different MRR ID must not manufacture a second support.
Use a checked origin mapping and reject circular support without a separately
admitted recursive interpretation. G0--G2 below accept only acyclic proof use.

* Direct Scheme ABI migration

The user subsequently required removal of project JSON transport and benchmark
artifacts. The replacement semantic ABI is version 2 with inert Scheme data;
Rust consumes original native MRR candidate/receipt values and re-admits them
through the MRR owner. The older JSON exporter remains an upstream MRR feature,
but POO no longer uses it. Physical cross-process exchange must implement a
versioned native projection at the owning boundary, retaining original identity
and admission semantics; it must not reintroduce JSON as a compatibility lane.
ASP Scheme benchmark API owns new measurement and receipts. DeepSeek HTTP
encoding is confined to the provider adapter. Historical receipts qualify only
the old producer artifact.

* Identity, clocks and the correspondence contract

Proposed =TemporalMrrCorrespondence= is a POO-owned admitted value. The wire
encoding is a projection of that value, not a public construction DSL. Its
checker binds the following independently named fields:

- Profile/schema version, producer/checker artifact and canonical encoding.
- Source owner, source identity, exact revision inventory and root content ID.
- Journal identity, admission cut, optional valid-time selector and projection.
- Temporal host generation and native MRR GenerationId, stored separately.
- Original parser/compiler/source receipt, query binding, both catalogs,
  SemanticSnapshot, ordered result digest and row count.
- Clock domain/role and coordinate interpretation; explicit conversion proof
  when supported. No use of generation or receipt arrival time as event time.
- Policy, principal/scope, dependency inventory and coverage evidence references.

The host supplies the trust root for registration; a digest binds bytes but
does not authenticate that host or source. Map one logical projected source to
one content revision per MRR snapshot. If a Temporal cut has competing revision
heads, project an explicit conflict inventory under one source revision, or
reject the requested single-valued profile. Do not let snapshot canonicalization
silently choose one temporal branch.

Derive exported MRR IDs from a versioned, domain-separated canonical mapping
through MRR identity constructors. Keep an explicit map back to immutable POO
revision and proof identities. Use source namespace plus logical event identity;
two providers using the text "event-1" must not collide. Preserve original MRR
row ordering and duplicates in its receipt. A Temporal projection may reject or
explicitly account for duplicates; it must retain the untouched original value.

Changing the cut, valid-time selector, profile, policy or clock mapping creates
a new correspondence even if the projected cell values happen to be equal.
Multi-source queries bind the complete source revision vector, not one latest
integer. Resource budget is execution metadata; it cannot change model truth
or turn a truncated enumeration into a complete one.

* Typed relation profiles

These are proposed semantic relation families. Names below are explanatory,
not new callable APIs. POO defines their meaning; an admitted versioned MRR
catalog defines field types and authority. Start with the existing scalar ABI
and add new native profiles only with their own differential acceptance.

| Family | Essential payload | Admission requirement |
|--------+-------------------+-----------------------|
| Observation revision | Source/event/revision, observed/declared/missing kind, predecessor, coordinate or interval, clock | Explicit provenance and distinction between observation and assumption |
| Evidence cut | Journal, admission selector, valid-time selector, visible revision set, conflict status | Replay from the immutable journal; no caller-authored selected heads |
| Coverage | Source/partition set, scope, frontier, query/program, completion status | Owner evidence for the exact closed domain; a watermark alone is insufficient |
| Conclusion revision | Subject, predecessor, profile, model/query, classification, cut/projection, proof | Native owner proof admission; immutable revisions including tombstones |
| Support group | Conclusion, derivation identity, conjunctive premise set, alternative group, polarity | Resolvable premises and independently checked derivation semantics |
| Applicability | Conclusion, source vector, policy/authority epoch, scope, selection version, status | Checked current-state binding at the intended use boundary |

Intervals require explicit endpoint/inclusivity and uncertainty semantics.
Cross-clock relations require a checked conversion profile. Missing evidence
must remain represented as missing; never synthesize zero coordinates or a
negative fact. Precedence, causal dependence, derivation dependence and effect
authorization remain distinct relation types.

Preserve Temporal family-relative =possible/necessary/refuted/unknown= in its
profile. Do not cast =necessary= to MRR TRUE without the interpretation and
admitted proof premises. MRR truth states TRUE, FALSE, UNKNOWN, INCOMPLETE,
STALE and CONFLICT also remain distinct. A budget stop is INCOMPLETE; source
coverage gaps are UNKNOWN; obsolete applicability is STALE. An empty backend
answer establishes FALSE only with a checked bounded closed-world argument.

* Evidence admission and physical execution

Proposed admission is staged: source-bound -> typed-result-admitted ->
projection-checked -> proof-admitted -> currently-applicable -> authorized-use.
Every stage preserves earlier evidence and states exactly what it established.
Failure or missing evidence leaves the later stage unavailable.

For a physical roundtrip, use MRR's original source compiler/binder, execute
against the exact restored MRR Data root, retain the physical execution record,
export original candidate plus receipt, and re-admit with the same authentic
bound query. The correspondence checker then verifies the supported projection.
Backend trust must be explicit: either a trusted pinned executor is the stated
premise, or an independently replayable derivation is required. A hash of an
execution report is not proof that the execution happened correctly.

Coverage has three independent gates: source inventory, query evaluation and
Temporal hypothesis/behavior enumeration. Completion at one gate does not
close the others. Unbounded source discovery, unsupported projection, truncated
rows and exhausted budgets produce typed non-completion outcomes.

A physical-empty answer is valid transport but cannot enter today's nonempty
event/position profile. Add an explicit empty/absence profile only with coverage
and nonmembership evidence; do not weaken the existing rejection implicitly.

* Late evidence, alternative support and recursion

1. Admit a source correction/retraction into a new immutable journal revision.
   Advance the registered current source fence and mark dependent current
   selections dirty before making the new current view visible.
2. Compute the affected frontier from a bound dependency inventory. Include
   positive facts, absence scopes, clock conversions, source coverage, policy,
   valid-time selector and authority leases. Unknown inventory completeness
   forces conservative scope-wide invalidation; "unaffected" is only relative
   to the admitted inventory.
3. Reevaluate support groups. For supports ={a,b}= OR ={c}=, removing =a=
   invalidates the first derivation; the conclusion survives if =c= remains
   admissible. Issue a revised proof and revision for the new cut even when
   the displayed classification stays unchanged. Invalidation is scheduling,
   not a proof of refutation or retraction.
4. For positive recursion, stabilize the impacted SCC from surviving external
   support under a named checked evaluator. An isolated cycle must not sustain
   itself after its last external premise is removed. MRR's present lineage
   DAG cannot directly represent cyclic justification semantics: store finite
   proof witnesses separately from the dependency SCC graph.
5. Negation/aggregation requires a declared stratification or another explicit
   interpretation and scope-complete evidence. Non-stratified or unsupported
   programs stay unsupported. A budget stop keeps current selection dirty;
   it cannot publish either the old answer as current or a new FALSE.

Declared acyclic support evaluation and original positive proof binding now
implement part of step 3. Complete support inventories and steps 4--5 require
new executable gates. The existing Temporal reverse index
and MRR impact traversal implement useful frontiers, not this stabilization
algorithm. Before incremental reuse is qualified, full recomputation of the
affected declared scope is the reference implementation and test oracle.

* Durable publication, current reads and Context

The existing SQLite store atomically commits one initial pointer and historical
receipt. Extend it only after durable proof material is resolvable and replayable.
Proposed =read-current= must verify selected revision, dependency source vector,
policy/grant fence and scope; return applicable, stale/dirty, conflicted or
unavailable explicitly. Historical receipt lookup remains a separate operation.

Use one local coordinator transaction for source-fence advance, dirty selection
state and durable outbox entry. Content-addressed MRR materialization can happen
before this transaction and remain unselected until commit. Publish a new
selection only after its immutable snapshot/proof is available and all expected
fences still match. Outbox replay is idempotent by immutable operation identity;
reordered deliveries cannot move the current frontier backwards. This is a
proposed runtime extension, not functionality of the current first-root store.

For remote source owners, "current" means relative to an admitted source vector
and freshness policy. Global instantaneous freshness requires a source-owner
lease/fence protocol; do not claim distributed atomicity across SQLite, MRR Data
and remote providers. A current read alone also cannot authorize a later effect:
the effect executor must consume/recheck the bound authority and freshness fence
at its commit boundary. Unsupported external fencing leaves that effect gate open.

Export Temporal receipts into MRR Context as exact FactId references with their
dependency closure. Context selection checks applicability for its actor/task/
policy and destination before materialization and again where required at use.
A source update invalidates eligibility for future reuse; it cannot erase bytes
already disclosed to a model. IFC labels, provenance, leases and declassification
need an explicit Agentic AI Lab decision. Context evidence admission, Temporal proof
admission and information-flow permission are separate checks bound to one
payload; none can be inferred from a model's agreement with tool output.

* Rust layout and optimization constraints

Keep the native lifetime/queue/transport adapter in MRR =runtime/=. Keep
query admission in MRR and physical IO in MRR Data. Add POO-native projection,
correspondence and applicability objects in the Temporal module; expose only
bounded ABI operations required by the runtime. Trusted registration/publication
must remain host capabilities separate from model-callable read-only tools.

Cache immutable compilation separately from snapshot-bound query results and
proof/applicability state. Keys include the relevant original identities,
projection/profile, source vector and policy scope. Reusing proof bytes never
reuses an expired applicability decision. Bound total bytes, rows, cells, depth,
support edges and queued work before expensive allocation; reject partial
transfers rather than silently admitting their prefix.

Measure cold/warm physical bytes, native queue delay, proof time, copied bytes
and peak memory separately. Optimize affected-frontier work only after comparison
with full recomputation. Current native timeout abandons a response, not the
owner-thread execution; cancellation must preserve terminal native lifetime and
bounded admission. Performance claims need measured workloads and exact pins.

* Delivery gates and falsifiable acceptance

| Gate | Owned change | Required evidence |
|------+--------------+-------------------|
| G0 physical read-only | MRR Data original typed transport; immutable MRR pin migration; POO correspondence check | Original GQL -> restored physical root -> original MRR receipt -> native Temporal; changed root/source/query/catalog/row and empty answer controls |
| G1 reverse projection | POO conclusion/cut/receipt relation profile; MRR typed fact admission | Roundtrip preserves original identities, conflict/tombstone/history and classification scope; forged proof and self-support reject |
| G2 acyclic revision lifecycle | POO support groups and durable journal; runtime dirty/current fences; MRR Context dependency use | Late correction, dual supports, last-support removal, absence dependency, policy expiry, stale Context and as-of replay |
| G3 recursive/absence profiles | Named evaluator plus SCC/coverage certificates and POO replay | External-support removal breaks cycles; unsupported negation rejects; incremental results equal full recomputation; budget leaves dirty |
| G4 authorized publication | Runtime replacement/tombstone CAS, resolvable proof journal, IFC and effect fences | Concurrent source update vs commit, policy revocation, outbox reorder/duplicate, crash at every durable boundary, stale effect reject |
| G5 real-model lifecycle | Frozen model task/tool profiles over the implemented gates | Real physical query, correction and re-query; model consumes stale/incomplete/refuted outcomes correctly; five-second genuine-content watchdog, no hidden retries |

G0 is the next implementation slice; G1 and G2 turn the current one-way adapter
into the first useful lifecycle integration. G3 and G4 must qualify before
general causal-maintenance or authorized-effect claims. Real-model read-only
acceptance remains valid for its original profile and does not substitute for
these deterministic negative/race gates.

Mandatory scenario: two independent derivations establish a claim at cut A;
a late correction removes one at cut B; the claim remains with a changed proof;
removing the last support at cut C makes the current selection unavailable until
reevaluation establishes the appropriate unknown/refuted/retracted outcome.
Historical queries at A and B must reproduce their original results. Repeat
with an absence premise invalidated by a newly arriving event, a valid-time-only
change, a conflicting source branch and an expired policy. No case may preserve
a current permit merely because its historical commit receipt still exists.

* Proof-bound Family revision Library slice

The public =lifecycle/interface= connects a replayed Family admission to the
existing immutable conclusion envelopes. =family-revision-root= retains the
admission's original proof. =family-revision-change= replays both admissions,
requires the same logical Source, model, query and claim, an advancing Source
generation, and a complete scoped invalidation frontier bound to both cuts and
projections. Classification equality does not reuse the historical proof:
correction produces a new proof-bound revision with an explicit predecessor.

=retract= requires a previously possible/necessary admission and a newly
replayed refuted admission for that same Family query. The resulting tombstone
retains the refutation proof and all predecessors. Invalidation alone cannot
produce it. =family-revision-replay= reconstructs every predecessor and checks
the proof, revision and digest bindings; =family-revision-journal= also checks
the supplied journal inventory through the existing conclusion graph validator.
Omitting a predecessor or continuing a withdrawn branch rejects admission.

This is pure Scheme Library behavior. The frontier's completeness and Source
cut remain caller premises; there is no authenticated index/current-cut
correspondence, durable append, support stabilization, native ABI journal
transport, current-pointer CAS or effect execution. Retraction is query scoped;
it does not establish that all independent supports for a business claim have
been removed. Runtime-executed, Source-authenticated and action-authorized
flags remain false. G1--G5 retain their independent gates.

The later =9bf708ec= pinned physical qualification supersedes the historical
initialization failure for its recorded read-only graph: Data =707f4353= and
MRR =d5beb403=. Its successful receipt is in
[[file:../../t/qualification/temporal-current-source/README.org][the current-source qualification archive]]. It does not qualify this new lifecycle
slice's ABI transport, durable journal or publication behavior.

The next ownership sequence is:
1. POO extends the native Scheme ABI with proof-bound revision/journal transport
   and replay refusal receipts; Rust forwards the original typed identities.
2. MRR projects admitted revisions into Context with explicit classification,
   predecessor and Source scope. It must preserve multiple independent support
   groups and keep dirty/current eligibility separate from historical validity.
3. MRR Data Backend/Protocols persist the proof journal before a current-pointer
   replacement or tombstone CAS. Crash/replay/concurrent-cut and policy tests
   qualify this boundary before any effect fence or real-model lifecycle gate.

Each step requires its own pinned cross-runtime receipt. The Library slice
does not supply those receipts or choose a business-level current winner.

The native public Library qualification passed 11/11 Cases (seven lifecycle,
four current-source regressions), final =OK= and exit 0 under five-second
genuine-progress and 45-second total gates. The frozen Scheme receipt and
original output are in the qualification archive linked above. Four earlier
discovery timeouts remain archived; bounded, completed official dependency
imports resolved the observed silent loading stage. No business or model calls
were used to substitute for these Library checks.

* In-process revision/journal ABI slice

The POO Rust Library now connects original admitted MRR values to the Scheme
Family lifecycle owner. =MrrFamilyAdmission::revision_root= and
=MrrFamilyRevision::change/journal= use three native Scheme datum v2 operations.
The original admission and proof objects stay on the native owner thread;
caller payloads name retained handles and a declared scoped frontier. Scheme
replays admissions and predecessors, then projects original proof, revision,
classification and Source scope fields. A supplied proof field cannot override
an owner value. Correction/retraction branches coexist without selecting a
current winner; current Source applicability is still a separate query.

Revision history and journal inventory are bounded to 128 entries, frontier
identities to 128 characters and each frontier list to 128 identities. Capacity
refuses new revisions while retaining idempotent existing handles. The journal
response has per-entry admission/revision digests and classification, in
addition to the original conclusion envelope fields.

The original MRR query/candidate/receipt regression passed through the actual
native C ABI with both debug and release Rust executables, exit 0, five seconds
without genuine output as failure and a 45-second total deadline. It covers
proof-bound correction/tombstone, retained classification/history/branches,
missing/duplicate/unknown inventory, partial frontier, wrong cut, extra proof
field, identity bounds and capacity refusal. Exact artifact/source/pin receipts
are in [[file:../../t/qualification/temporal-family-lifecycle-abi/README.org][the lifecycle ABI qualification archive]]. One initial omitted-trace
exit-124 failure remains archived; enabling existing completed hash/native-call
events qualified the same debug artifact without widening either deadline.

This slice lives in the POO adapter; MRR Context and MRR Data retain their
separate ownership. Handles are process local. The projected journal lacks a
restartable full-premise archive and is not suitable as authoritative durable
history by itself. Frontier completeness/index identity remain caller
premises; Source-authenticated, action-authorized, runtime-executed and durable
flags remain false. Full proof transport/replay, multi-support stabilization,
Context dirty/current fences, backend append/recovery and current-pointer CAS
remain required before publication and real-model lifecycle gates. The earlier
physical and model receipts continue to qualify only their frozen graphs.
