#+TITLE: Native Context service and the C ABI boundary
#+LANGUAGE: en

* Scope correction

Scheme owns Context/Session lifecycle semantics, ASCENT proof/support and the
persistent journal. Bindings expose C ABI declarations, copied byte ownership,
status and release rules. Rust is a later downstream consumer. No Rust runtime,
Tokio scheduler, Rust build script, fixed executable path or Rust-specific VM
setup adapter belongs in this integration step.

The premature Rust consumer and its binding wrappers were removed from the
working tree. Diagnostic artifacts remain under
=/private/tmp/context-service-20261026=; they are not current product delivery.
Earlier 28 evidence retains its original scope and is not silently promoted.

* Existing C boundary

[[file:../../../../bindings/runtime-c/include/agentic_ai_lab/semantic.h][semantic.h]] already defines the versioned inert-byte call, trusted Host lanes,
thread-affine open/close and owner-side result release. The optional
[[file:../../../../bindings/runtime-c/include/agentic_ai_lab/scheme_native_v1.h][Scheme-native header]] defines copied result ownership for AOT-linked consumers.
[[file:../../../../bindings/runtime-c/README.org][The existing C ABI contract]] is authoritative. This change adds no binding file
and does not introduce another JSON wire protocol or VM bootstrap framework.

The Context lifecycle declaration and Scheme dispatch now use that existing
C ABI: =agentic_ai_lab_semantic_v1_context_command= is the trusted mutation
lane and =context.lifecycle.inspect= is the ordinary read-only operation.
[[file:../../../../modules/workflow/runtime/context-lifecycle.ss][The native adapter]] accepts an application-installed service capability; inert
request bytes cannot install a service or reconstruct an observation.

Qualification has two distinct boundaries. [[file:../../../../t/context-c-abi-test.ss][The in-process C caller]] exercises
active Context/Session decisions inside a heap-fenced Gerbil host, whose setup
and teardown are supplied by that host. The standalone packaged-artifact probe
exercises actual Gambit setup/cleanup but installs no live Context. Neither
alone qualifies a standalone artifact with active Context service installation,
Rust integration or distributed execution. Current-source complete-queue and
remote CI admission remain required.

* Native implementation

[[file:../../../../modules/ai-agentic-context/runtime-service.ss][The POO-native service]] reuses the existing Context owner and independent
Session terminal CAS. The trusted native caller binds original observation
capabilities; request identities are inert durable inbox keys, not Session
identities or proof capabilities. The document ID above is only an Org anchor.

Mutating requests check the owner epoch before inbox admission and again
before the effect. [[file:../../../../modules/ai-agentic-context/durable-owner.ss][The existing durable adapter]] stores the exact original
request and original decision in the same transaction as the effect. A retry
returns historical data without another terminal CAS. Same ID with changed
input is refused. Grant revocation uses the existing version CAS and support
graph, invalidating affected A/B consumers while independent C remains valid.
Cancellation/recovery cannot reactivate an old result.

Shutdown drains and joins the existing owner and closes its journal. It also
works before the first business command: original evidence remains checked,
but no propagation event or Attempt terminal is fabricated for cleanup.
