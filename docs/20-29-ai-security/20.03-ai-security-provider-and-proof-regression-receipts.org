#+title: 20.03 AI Security Provider and Proof Regression Receipts
#+startup: overview

* Status

Draft implementation receipt.

* Purpose

This document turns provider, evidence, and proof-closure failures discovered
while implementing the composable AI security architecture package into
versioned regression obligations.

It is not an AI security architecture, an engine layer, or a new Agentic AI Lab
public interface. Agentic AI Lab remains the general composition engine. These
receipts record whether a concrete toolchain can preserve the semantic,
evidence, and proof boundaries selected by a composed architecture package.

* Receipt envelope

Every regression receipt MUST record:

- receipt identifier and schema version;
- owning repository, package, and runtime artifact digest;
- exact action or structural selector;
- expected owner and projection boundary;
- observed provider, project root, or declaration closure;
- fail-closed outcome;
- proof-coverage effect;
- unknown or escalation classification;
- independent replay command and replay result;
- required property test or theorem before closure.

A receipt is closed only when the regression test fails against the defective
artifact, passes against the repaired artifact, and can be replayed without the
original agent session.

** Project-root counterexample

** Project-root refinement

** Project-root regression obligations

- property test: a supplied existing workspace resolves to an existing package
  root;
- negative property: transport labels cannot satisfy the project-root type;
- nested-package test: the same owner is stable when entered from the Git

provider ABI method token emitted by =LocalNativeCliBackend::push_method=; it

* ASR-RESIDENT-ENDPOINT-004

** Resident endpoint intent

resident runs the current runtime-binary digest. Nevertheless, exact query

global daemon and unreachable workspace resident starts a replacement
workspace process but does not reconcile the endpoint state.

** Resident endpoint refinement

Resident ownership MUST bind process identity, runtime digest, transport

reconciliation receipt. Process existence alone MUST NOT imply readiness.

** Resident endpoint regression obligations

- lifecycle test: replacing a stale daemon converges to one reachable owner;
- negative property: unreachable endpoints cannot report =healthy=;
- epoch test: a replacement process cannot inherit a stale owner election;
- replay receipt: the health decision can be reconstructed from process,
  digest, endpoint, and epoch evidence without live session history.

* Enterprise metrics

These receipts contribute to three separate metrics:

- proof coverage: the proportion of runtime projections whose complete
  cross-owner declaration closure receives an independent AXLE receipt;
- unknown and escalation rate: the proportion rejected because provider,
  project-root, namespace, or endpoint evidence is insufficient;
- replay success: the proportion of historical decisions reproducible from
  versioned receipts without the original agent, resident process, or hidden
  transport state.

Provider availability or a green Lean build alone does not increase proof
coverage. A fail-closed unknown is a valid safety outcome, but remains visible
in the escalation metric until its regression receipt closes.
