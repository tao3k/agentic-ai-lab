#+title: Native Temporal current-source evidence

Raw execution logs are local or CI artifacts and are not retained in the
source checkout. Historical structured summaries do not qualify a newer source
cut; run the executable gate again for current evidence.

This slice retains the original native family admission, replays its premises,
and compares it with a host-selected current source. The Scheme owner decides
current/stale; the Rust library controls the native owner queue and forwards
verified original MRR observations. Every authority/effect flag remains false.

=native-test.ss= delegates to upstream gxtest's =main=. Its four applicability
cases and seven =t/temporal-lifecycle-test.ss= cases use the public
=yuanxu-test-case= helper.
Compile through the official Gerbil compiler, with native dependency inputs
selected explicitly. Run the executable through a five-second genuine-output
watchdog and a 45-second total deadline, passing =-v 5= and the original test
files. Discovery, assertions, Case profiles, reporting and status remain gxtest
owned. A compiled binary alone is not a passing test result.

Always compile the entry module before linking its executable:
#+begin_src sh
gxc -O -static t/qualification/temporal-current-source/native-test.ss
#+end_src
Then use official =compile-exe= and =execute-pending-compile-jobs!=. Linking
alone can reuse installed static code that predates a source edit. The entry's
static compiler output must contain the current completion diagnostics, and
the run must enable =AGENTIC_AI_LAB_TEST_PROGRESS= to expose those real boundaries.
The entry also imports named dependency contexts through the official expander
before gxtest discovery, reporting only completed imports. A single stalled
import still fails the five-second gate. Compile changed dependency and test
modules before compiling the entry; never reuse stale installed static code.
