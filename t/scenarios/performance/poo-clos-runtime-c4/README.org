#+title: POO CLOS runtime C4 ownership scenario

This Scenario proves that POO CLOS does not maintain a second class precedence
algorithm.  It builds the standard pedalo counterexample and compares every
public class metaobject by =eq?= with the class pointer projected from the
complete upstream =compute-precedence-list!= result.

The Scenario imports the class owner directly; it does not load lifecycle,
dispatch, load-form, reflection, or declaration syntax merely to measure C4.
The graph is reconstructed for 40 timed samples with fresh class identities.
The same process then records 40 warm public precedence reads.  Timing values
are diagnostic receipts, not a claim that a copied linearizer competes with
upstream POO.  Acceptance is semantic: runtime order, exact metaobject identity,
and =parallel-cpl=#f= must all hold.

Run from the repository root:

#+begin_src sh
just benchmark-poo-clos-runtime-c4
#+end_src
