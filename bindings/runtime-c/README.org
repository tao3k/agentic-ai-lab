#+title: Runtime v0.1 C Bindings

This directory owns the installed pre-v1 C control-lane ABI.  It contains no
graph-plan compatibility API and exposes no Gerbil, Gambit, Python, or Scheme
heap type.

| Owner | Path |
|-------+------|
| Public C11 header | =include/agentic_ai_lab/runtime_v0.h= |
| POO-native ABI schema | =src/contract/runtime-v0-abi-schema.ss= |
| Control contract notes | =schema/runtime_v0_control.org= |
| Handle/lifecycle engine | =src/runtime_v0.c= |
| Pure C harness | =tests/runtime_v0_harness.c= |
| Hot/bulk harness | =tests/runtime_v0_batch_harness.c= |
| Installed consumer | =tests/runtime_v0_installed_consumer.c= |
| Relocatable SDK metadata | =pkgconfig/agentic-ai-lab-runtime-v0.pc= |
| Scheme-native C header | =include/agentic_ai_lab/scheme_native_v1.h= |
| Scheme semantic owner | =src/ffi/runtime-v0-native.ss= |

The Bundle remains the semantic owner.  The C engine owns negotiation, opaque
handles, lifecycle state, checkpoint envelopes, owned bytes, and typed boundary
errors only.

Hot headers are fixed native structs with an explicit =header_stride=.  The v0
lane requires that stride to equal the generated header size, rejects
count/stride and payload-range overflow, and uses one =lower_bound= followed by
an ordered sequential merge for total batch lookup cost =O(log n + k)=.

Run the focused gates:

#+begin_src sh
bazel test //bindings/runtime-c:runtime_c_tests
bazel test //bindings/runtime-c:runtime_c_sanitizer_tests
bazel test //bindings/runtime-c:runtime_c_leak_test
bazel test //bindings/runtime-c:runtime_v0_batch_benchmark_smoke
bazel test //bindings/runtime-c:runtime_v0_gerbil_ffi_benchmark
bazel build \
  //bindings/runtime-c:runtime_c_static \
  //bindings/runtime-c:runtime_c_shared
#+end_src

=runtime_c_tests= includes a parity test between the Scheme-generated Bazel
contract outputs and the checked-in header/vector artifacts.  The contract rule
has an explicit dependency on =//:runtime_v0_schema=, so schema edits invalidate
generation and all downstream C consumers.

Bazel is the external runtime-C action graph.  =build.ss= remains the native
Scheme build authority and is not called or replaced by these C targets.

The =Runtime C SDK= workflow owns this ABI independently of the Scheme package
CI.  On Linux and macOS it validates the generated Scheme contract/header
parity, the exported symbol allow-list, pure installed consumers, handle and
arena lifecycle, batch behavior, and platform builds.  Linux additionally runs
UBSan, ASan, Valgrind and the bounded performance smoke.  Its relocatable SDK
contains both static and shared libraries, the public and generated contract
headers, the symbol manifest and =pkg-config= metadata.

Rust, MRR, Python and other runtimes bind this C11 surface directly.  They do
not import Gerbil heap objects, discover Scheme source paths, or launch a
Scheme subprocess.  A Rust =build.rs= may use =PKG_CONFIG_PATH= pointing at
=lib/pkgconfig= or link =libagentic_ai_lab_runtime_v0.a= explicitly; generated Rust
types must remain projections of =runtime_v0.h=, never an independently owned
protocol.

The optional Scheme-native ABI is a separate, AOT-linked C surface for POO
Flow-owned contract semantics.  It follows Gerbil's =begin-ffi= contract:
=c-define= exports versioned symbols, =define-c-struct= types the borrowed
result pointer, and =agentic_ai_lab_scheme_result_v1_release= is the sole owner-side
release operation for copied payload bytes.  It currently exposes a descriptor
and bounded validation for source-query receipts, Query execution candidates,
language-admission receipts, and artifact-projection receipts.  The generic C
ABI remains a descriptor and JSON-validation boundary.  Native Query producers
consume the Scheme-owned function IR in =bindings/rust-ir= through
=gerbil-scheme-rust-ir=; no Query-specific C structure duplicates that model.
Unsupported contract names and malformed payloads fail closed with
=agentic-ai-lab.scheme-native-error.v1= bytes.

The ordinary Runtime C SDK does not contain a hidden Scheme VM and therefore
does not ship =scheme_native_v1.h= by itself.  Downstream AOT packages include
that header together with the compiler-produced Gerbil program archive and
runtime initialization stub.  The ordinary native Scheme build and gxtest lane
compile this module and execute a real C caller inside the Gerbil host,
covering symbol resolution, ABI version, byte ownership, validation and
idempotent result release.  The independent Runtime C workflow remains a small
pure-C/header/sanitizer boundary and does not rebuild the Gerbil package graph.

The installed contract is ABI v0.1 and Bundle schema
=agentic-ai-lab.organization-bundle.draft.3=.  Neither is an ABI v1 freeze claim.

* Registered Host policy through fixed ABI v1

The native semantic AOT library now exports
=agentic_ai_lab_semantic_v1_policy_refresh= for trusted Host policy and observed-time
registration. Python calls =SemanticRuntime.refresh_temporal_policy=; Rust calls
=SemanticRuntime::refresh_policy=. These helpers are Host controls and must not
be exposed as model tools. Ordinary =agentic_ai_lab_semantic_v1_call= rejects all
=$host.= operations with transport status 3 before Scheme dispatch. The
ordinary descriptor lists =temporal.support.guard=, never policy registration.

The strict inert Scheme request uses schema
=agentic-ai-lab.temporal-policy-refresh-request.v1= and exactly =policy=, =generation=
and =effectiveAt= fields. Policy contains =identity=, =revision=, =start= and
=end=. Each instant has =identity=, =domain=, integer =coordinate=,
=provenance= and =modality= equal to =observed=. The original native POO policy
and opaque Host registry own window validation, clock-domain checks, monotonic
per-policy generation/time, immutable revisions and the 128 current-policy /
128 historical-revision bounds. An identical same-generation registration is
idempotent. All checks precede registry mutation; rejected updates preserve the
previous snapshot.

The ordinary guard request has schema
=agentic-ai-lab.temporal-support-guard-request.v1= and exactly =expectedGeneration=,
=expectedPolicyDigest= and =task=. Task is the existing bounded support request.
Python uses =guard_temporal_support=; Rust uses
=call("temporal.support.guard", &request)=. The guard reads the registered
policy/time; caller-supplied clock, policy or proof fields reject. Unregistered
or stale generations reject. A stale policy digest returns =stale-policy=;
otherwise the native [start,end) window returns =not-yet-effective=,
=applicable= or =expired-policy=. The embedded support evaluation remains
available even when policy applicability is false. Consumers must check both.

This is in-process Host registration, not provider clock authentication or an
automatic refresh. All proof, source authentication, selection, action and
durability flags remain false. The guard does not publish Data or perform CAS.
Runtime opening, owner-thread serialization, borrowed input/copied result and
terminal close rules are unchanged. The current clients require the added
policy-refresh symbol and validate the configured artifact digest. Schema and
ABI remain v1, with no fallback transport.

Executable C/Python/Rust evidence, original cross-language datum parity and all
failed attempts are retained in
=t/qualification/temporal-library-basic/host-policy-abi-v1/=.

* Trusted original Derivation admission through ABI v1

=agentic_ai_lab_semantic_v1_derivation_admit= is a dedicated trusted Host entrypoint.
Ordinary/model calls cannot dispatch =$host.temporal.derivation.admit=. Python
uses =SemanticRuntime.admit_temporal_derivation=; Rust uses
=MrrDerivationProjection::verify_native= with original retained owner records,
typed =MrrTemporalSourceBinding= values and the original Temporal journal.

The strict inert Scheme v1 request has schema
=agentic-ai-lab.temporal-derivation-admit-request.v1= and exactly =projection=,
=journal=, =sourceBindings=, =workSteps= and =maximumNodes=. Projection is the
original =agentic-ai-lab.mrr-derivation-projection.v1= Rule/Catalog/Fact/Derivation
projection. Source bindings each contain =fact=, =subject= and =revision=;
callers supply no proof nodes, proof flags or completion claims. Journal uses
the existing support journal shape. All inventories and field sets are bounded;
work steps are 1..4096 and proof nodes 1..128. Source rows use the existing
int64/boolean profile and must agree with projected Catalog column types.

The native POO program constructs the original ASCENT query for the selected
output from exact source rows and original Rules. The original Scheme producer
and positive-proof verifier recompute source-relative truth. Rule node labels,
original direct Derivation input FactIds, output root, all transitive source
leaves and journal content/revisions must jointly agree. There is one original
Derivation per derived FactId and one exact rooted correspondence; alternative
support completeness is outside this bounded profile.

The result carries native =proofAdmitted=, =mrrRuleEquivalenceVerified= and
=derivationCorrespondenceVerified= plus the selected root identity, digests,
node correspondence and ordinary support. Rust additionally checks the response
against its retained original root/rule/catalog/generation. The support's proof
label equals the joint binding digest. Source authentication, selection, action
and durability flags remain false. Later source correction invalidates current
support while the historical cut remains supported.

This operation is pure admission against Host-declared snapshots. It neither
retains a current admitted-proof registry nor authenticates the source provider,
refreshes authoritative state, joins the registered policy guard into a final
effect fence, or publishes Data. Returned datum receipts are evidence of this
call, not a transferable effect grant. Native result ownership, terminal close,
thread serialization and artifact digest validation remain unchanged; current
clients require the added symbol. Transport, schemas and ABI remain v1.
