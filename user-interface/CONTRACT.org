* Purpose

** Upstream Kernel Profile

The maintained kernel module implementations are upstream-owned under
=modules=:

- =modules/funflow/config.ss= owns =(flow funflow +functional +dag +typed-receipts +runtime-manifest)=.
- =modules/governor/config.ss= owns =(loop governor +strategy +policy)=.
- =modules/nono-sandbox/config.ss= owns =(sandbox nono-sandbox +nono +doctor)=.
- =modules/cubeSandbox/config.ss= owns =(sandbox cubeSandbox +cube +doctor)=.

=user-interface/init.ss= exports enabled category/module/feature rows.
=user-interface/config.ss= imports the canonical composition constructor and
directly composes already maintained Profiles and Standards. Reusable Profiles
and Scenarios remain separately importable modules; the root does not scan or
re-export them and does not declare a stage, graph, loop, proof, handoff,
Provider or runtime DSL.

This directory models the downstream repository surface that a Agentic AI Lab user
would maintain. It is intentionally root-level and separate from =src=. Agentic AI Lab
is the brand name. Bare =poo= remains only a Scheme/API prefix for Gerbil POO
helpers and should not be used as the user-visible product or module group
identity.

The downstream surface follows the project invariant: Agentic AI Lab is 100% POO-native and functional-first. Users extend upstream-owned objects and functional flow constructors; they do not author a parallel alist/record DSL, expose raw merge code, or maintain direct =(lambda (self super) ...)= compute hooks as normal configuration.

The files here stay declarative:

- =init.ss= lists optional feature patches/custom modules through =yuanxu!= category rows.
- =config.ss= uses the thin =user-composition= binding and directly composes
  maintained Profile and Standard values with explicit imports; operational
  responsibilities remain owned by those values.
- =custom/<module-name>/{types,objects,funs,config,interface}.ss= is the stable
  user-maintained module shell; concrete subowners remain precise imports.
- =profiles/*.ss= contributes stable reusable profile objects.
- =scenarios/<name>/scenario.ss= contributes reusable Scenario objects over
  those Profiles.

The implementation stays upstream:

- =src/user-interface/root-objects.ss= owns user-interface object contracts.
- =src/user-interface/root-profile.ss= owns profile/config projection helpers.
- =src/user-interface/declaration-case.ss= owns declaration case contracts for tools and tests.
- reusable descriptor and loader mechanisms live in =core/module-system/=; Agentic AI Lab descriptors, source policy, activation, and presentation live in =src/authoring/= and =src/user-interface/=, with domain behavior in =modules/=.

* Public Entry Points

The downstream repository has two root entrypoints:

- =init.ss= enables maintained, contributor and private custom module sources;
- =config.ss= declares the final Scenario composition.

Every custom module exposes =interface.ss=.  Its =config.ss= stays lightweight;
it must not aggregate every Profile and Scenario implementation into the public
module entry.
Reusable scenario fragments are also part of the teaching surface:
- =profiles/langchain.ss= and =scenarios/langchain/scenario.ss=
- =profiles/langgraph.ss= and =scenarios/langgraph/scenario.ss=
- =profiles/crewai.ss= and =scenarios/crewai/scenario.ss=
- =profiles/tool-calling.ss= and
  =scenarios/tool-calling-agent-loop/scenario.ss=

The presentation surface exposes ownership metadata so agents can inspect the
config without realizing descriptors or executing runtime hooks. Presentations
must include =presentation-trace= facts. Trace stages are report-only
observability data for catching lazy POO projection recursion; they must keep
=descriptor-realized? = #f= and =runtime-executed = #f=.

* Boundaries

- User-owned: root module selection, final compositions, reusable Profiles,
  reusable Scenarios and custom module declarations.
- Module-system-owned: settings, profile projection, profile-set validation, descriptor realization, validation, merge, doctor output.
- Runtime-owned: backend execution and handler lifecycle in =marlin-agent-core=.

Every downstream presentation must keep =runtime-executed = #f=. Kernel profile
module groups and presentation fields should expose =agentic-ai-lab= as the brand
identity.

* Doom-Style Init Shape

=init.ss= is intentionally closer to Doom's =init.el= than to an implementation
module:

- enable required workflow, loop, and sandbox modules through =yuanxu!=;
- group optional feature patches by category, such as =:workflow= and =:custom=;
- attach user-toggleable module features with =+feature= flags;
- keep object contracts, sandbox recipes, settings, and facade exports out of =init.ss=;
- keep sandbox recipes and non-object configuration out of root =user-interface=;
- keep object implementations out of root =init.ss= and =config.ss=;
- keep custom module bodies under =custom= so users have room to write their own modules.
