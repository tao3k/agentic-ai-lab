* Objective and prior taint diagnosis

The primary endpoint is cumulative actual provider thinking until the entire task first passes both independent query obligations, including all earlier failures and repairs. A subgoal or shorter second answer is not task completion. Only local tests and model requests were performed.

Previously the taint control used 4,783 + 2,842 = 7,625 thinking tokens, and native evidence used 5,821 + 2,550 = 8,371. The 746 increase decomposes into +1,038 before any native evidence exposure and -292 after exposure. The two first requests are byte-identical. That observation does not identify an engine regression or prove a negative causal effect of the evidence packet. It is one sampled pair with unequal first-call thinking.

This study shares ONE actual initial response between the paired policies. Both whole-task trajectories charge its entire observed usage; actual experimental expenditure counts the request once. This is a control for initial sampling variation. It does not reduce deployed first-call cost and is not itself a runtime optimization.

* Implementation and intervention

EvidenceChain.intermediates(reference, names) projects completed native facts under current source identity, native component fingerprints and path/result reference. It refuses final answer relations, unknown/incomplete components, duplicates and stale references. It scans native materialization rather than computing closures in Python. Only selected flow/permit or balanced relations are exposed to the model; no final answer set is supplied.

Native Trajectory verification now has task/subgoal scope. Subgoal success records a completed obligation and clears the adapter repair link, but cannot freeze whole-task first-success cost. Only a successful independently graded task event freezes that prefix. Unknown scope is rejected atomically. This avoids charging ordinary continuation as repair after a subgoal is repaired.

Both conditions keep actual provider reasoning/message history opaquely. After a real failed completed response, both receive the same scalar correction instruction; the treatment also receives applicable checked intermediates. After a successful first obligation, only the treatment receives those intermediates before the second query. All calls until both obligations pass belong to the primary endpoint. The first prompt is shared, conditions alternate continuation order, maximum three attempts per obligation, high reasoning, 131072 output-token cap, no server-side output schema.

* Task sources, complexity and independent validation

The finite tagged dataflow tasks adapt program-analysis use cases; scoped balanced-path tasks adapt the realizable-path motivation in [[https://doi.org/10.1145/199448.199462][Reps, Horwitz and Sagiv: precise interprocedural dataflow analysis via graph reachability]]. Recursive execution and mutation-sensitive oracles are informed by [[https://arxiv.org/abs/2609.37233][DatalogBench]]. These are newly generated experiments, not official benchmark reproductions or complete IFDS implementations. Fresh entities/structures do not prove training exclusion.

Tagged tasks join four node/tag requirements under tag-local sanitizers and conversion rules. The mutual variant has a flow/permit SCC. Balanced tasks require matching bracket labels, concatenation, context-local denied edges, supplied epsilon pairs, two simultaneous path conditions and scoped exclusions. Their state space, recursive joins and 96 requested classifications distinguish complexity from raw node count. The largest checked intermediate has over 1,200 rows. Independent oracle convergence takes up to 15 rounds.

Half the requested classifications are constructed using satisfiable intermediate tuples to avoid an all-negative task; the rest are randomly sampled. Requests are shuffled, but job identifiers retain construction indices. This construction correlation is a limitation: results are paired protocol observations, not a blind general benchmark of model intelligence. Complete-set grading still requires every requested classification, and the final query has different rules and expected sets.

All eight obligations agreed between an independently implemented Python fixed-point oracle and actual Scheme before model requests. A mutation replacing balanced paths with ordinary unlabeled graph reachability changes the oracle answers. One preflight source-wire issue (tuple rows versus canonical JSON arrays) was caught by source-authority admission and fixed before paid calls; admission was not weakened.

* Local ABI/API, Scheme, Lean and Quint qualification

Actual ABI and compiled API each passed five Trajectory/projection tests and nine Evidence DAG tests: 28 binding integration cases. Six direct Scheme ledger cases and seven experiment-intent tests passed. Lean verifies subgoal success does not freeze the task, alongside prefix accounting and invalidation. Quint healthy simulation passes 10,000 traces at up to 30 steps, seed 13; five weakened variants fail, including premature admission. This is bounded simulation and selected executable correspondence, not exhaustive exploration or universal native-source refinement.

No remote CI or publication was used. Package and API producer inputs bind the new scope implementation; API output hashes separately record Darwin signing/install-name transformation. Concurrent unrelated rule-source API changes are outside the frozen artifact used by this study and are reported as current-worktree drift if present. The study qualifies its artifact and selected tests, not every concurrent working-tree feature.
