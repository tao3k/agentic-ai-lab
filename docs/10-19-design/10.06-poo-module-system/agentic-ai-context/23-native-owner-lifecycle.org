evidence that an independent Session endpoint terminated. Original knowledge,
proof/support history, immutable terminals and pending reconciliation duties
remain durable data after a runtime scope is disposed.

* Diagnosis before production changes

A fresh unchanged legacy-cut baseline completed all 60 orders. The diagnostic
supervisor reported approximately 111 seconds, including up to one sampling
interval of process-exit observation lag. Samples showed RSS approximately
674--710 MiB and usually one current database's SQLite mappings/handles; they
did not show sustained linear FD growth. Garbage collection eventually released
old connections. Therefore the earlier timeout is not attributed uniquely to
an FD leak. Host scheduling/throughput variability remains a possible contributor.

The baseline, complete native transcript, ps/lsof samples and source/object cut
are retained under =/private/tmp/context-owner-baseline-20261026/=.

The source inspection identified deterministic lifecycle gaps: stop joined the
timer but retained its policy observer and clock capability; no adapter shutdown
closed its journal or detached Context subscriptions. Closed client handles
retained their owner thread. Cleanup depended on eventual GC. A separate
single-path phase diagnostic measured Context construction and persistence as
major work, while the former stop took about 0.00034 seconds because it did not
perform that resource teardown. That diagnostic is not a capacity qualification;
its transcript/cut are under =/private/tmp/context-owner-phase-20261026/=.

The command hot path also decoded the entire inbox for identity verification
and historical-ACK selection, repeatedly constructing inert POO values for
unrelated historical inputs. This unnecessary work grew with inbox history.

* Production responsibilities

| Owner | Change | Boundary retained |
|-------+--------+-------------------|
| Native change feed | Exact-identity unwatch; refuse detachment during pending/busy propagation | Do not discard prepared authority work or another consumer's subscription |
| Proof, grant, policy and Query publishers | Named unwatch wrappers through their existing serialized owner | No second observer registry or graph algorithm |
| Context runtime | Dispose its registered subscriptions, clear runtime references, reject subsequent use | Do not cancel Sessions, kill endpoints or create terminals; publishers retain original proof/history |
| Durable journal | Idempotent explicit close, rollback unfinished transaction, clear DB/owner/cut references, reject closed-handle reuse | Original inbox/evidence and last committed state remain; pending input is replayable |
| Durability adapter | Dispose its owned Context, close its journal, release captured resolver/authority/catalog references | Do not save an empty disposed Context over the committed checkpoint |
| Clock reactor | Quiesce client admission, join timer, detach exact observer/clock lease, close adapter, reject waiters/queued RPCs, clear runtime references | Late unreceived deadlines remain recoverable from durable tickets |
| Clock client | Serialize phase-check plus mailbox admission; join owner before retaining closed receipt; release thread reference | A closed receipt is diagnostic data, not effect authority |

The policy clock's released enrollment becomes a retired marker. It does not
reset to the never-enrolled state: current-use guards must refuse instead of
falling back to a frozen registered-time snapshot. A foreign clock capability
cannot release the live enrollment.

Context disposal is a distinct runtime operation from the existing Session
close/cancel protocol. It is owner-local and idempotent. It removes only the
observer values recorded by that Context. Normal subscription release requires
a quiescent feed; pending propagation is not silently drained or erased to make
a shutdown receipt look successful. A failed shutdown does not acknowledge
that all resources joined/closed.

=journal-input= performs indexed identity lookup and validates the selected
original payload digest. Normal retry verification and ACK selection use this
path. Full journal verification and recovery enumeration remain intact; the
optimization does not skip the final native integrity checks or original-input
substitution controls.

* Native positive and negative controls

=policy-clock-stop-receipt= is produced after the actual timer join and owner
join. Every scenario additionally checks the actual journal closed predicate,
disposed Context and zero Context subscriptions, while retaining references to
those handles. Repeated stop/close is idempotent; further Context/journal/RPC
use is refused. Neither GC nor process exit is used as the positive oracle.

An isolated negative adapter intentionally omits its teardown and misreports a
closed receipt. The native probe checks actual handles and detects an open
journal with three retained Context subscriptions. This is a deliberately
nonconforming adapter, not an alternative production shutdown path. It shows
why a declared receipt alone cannot qualify actual resource release.

The native unit probe checks pending-feed detachment refusal, exactly one
subscription, retention of another consumer's observer, retained original proof,
foreign-clock refusal, denial of frozen-time fallback, active-transaction
rollback and preservation of its pending input. An awaiting RPC is actually
registered with the owner before shutdown; it must receive explicit rejection
and join rather than time out.

A second native probe closes a paused durable owner with actual pending expiry
copies and active Attempts. Two duplicate transport copies share one immutable
inbox identity. The test retains that original ID and payload digest. The
independent Session endpoints remain running after controller shutdown, then
actually finish; their result strings alone do not create authenticated terminal
records. Another owner replays the preserved receipt and receives two real
rearmed timer copies. Cached A/B invalidation is inspected before use queries,
C remains admitted, each Attempt retains exactly one reconciliation obligation,
and no terminal is fabricated. The original bytes remain unchanged.

* Whole-process native gate

[[file:run-native-owner-lifecycle.py][The gate]] invokes the unchanged Just recipe once per profile with =all=.
Each invocation runs all 60 legal policy/expiry/result/cancel/recovery orders in
ONE gxi process, sequentially, with the existing pre-import 1 GiB heap fence and
150-second timeout. There is no chunking, forced GC, larger heap, changed source
window, removed negative control or shortened case set. Native diagnostic phase
tracing and ASCENT process tracing are disabled for capacity qualification.
External ps/lsof samples are retained without altering native resource limits.

The three profiles are canonical CAS, legacy name with CAS and historical
missing-cut input. The Python and Scheme order generators remain independent.
The runner requires all actual owner traces, original evidence/terminal checks,
60 actual close observations, zero exit and MODULE-OK/HARNESS-OK/final OK without
error markers. It captures exact source/object hashes before and after the run.
A saved replay token repeats the ENTIRE 60-order process on the identical cut.

The native unit/negative controls and a real Query-provider crash/recovery path
run serially after the capacity processes. Query subscriptions add the fourth
publisher kind beyond proof/grant/policy in the raw authority fixture.

* Executable SysML correspondence

[[file:23-owner-lifecycle.sysml][The model]] executes five teardown phases: admission quiescence, timer join,
subscription/clock retirement, journal close and owner join/acknowledgment. It
explores every phase permutation, no/one pending obligation and eight algorithms.
Incorrect phase orders are refused without a closed acknowledgment. Unsafe
algorithms omit journal/subscriber/clock cleanup, acknowledge before owner join,
lose a pending input, invent an endpoint terminal or leave admission open.

[[file:run-owner-lifecycle-model.py][The actual CLI runner]] checks the executed phase and outputs against an
independent prefix-order oracle, retains unsafe witnesses and reruns corrected
mode 0. It does not establish native timing, storage correctness or an unbounded
refinement theorem. Those remain distinct from the native whole-process gate.

* Limits of the claim

Explicit release and indexed inbox lookup remove confirmed lifecycle and hot-path
defects. A fresh old-code baseline passing shows why timing improvement alone
cannot prove that one defect uniquely caused the historical timeout. The final
claim is the measured complete cohort on its exact build and resource limits,
plus deterministic native release assertions. It is not a universal scheduling,
host-reboot, power-loss or remote-endpoint reconciliation guarantee. Resources
allocated by a bootstrap that throws before returning ownership remain the
bootstrap caller's responsibility; the reactor cannot infer undisclosed caps.
