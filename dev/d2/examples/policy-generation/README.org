* Existing source and intended question

This uses the unchanged existing =21-runtime-policy-transition.org= and
=21-policy-transition.sysml= under the Context design directory. The native
OpenSysML SDK selects the existing =ContextPolicyTransition::fixture= through
=view.sysml=. There is one native fixture occurrence, not five invented runtime
objects. The explanatory views show an illustrative owner generation 7 changing
to 8 while policy text remains the same. They are not recorded runtime
measurements or a new policy-state registry.

The question is why a command that captured generation 7 must still be refused
when content matches but the current registered generation is 8. The source
requires both expected generation and digest to match; a stale command receives
a durable refusal rather than an automatic rebase. Generation is the owner's
counter, distinct from an immutable policy revision. This small explanation
neither qualifies the complete trusted-capability boundary nor replaces the
existing executable policy contract.

* Model input and Module judgments

The POO case contains meanings, reader facets, source quotations, descriptions
and five local object illustrations. It has no direction, solver options,
handmade regions, coordinates, routes or whole-scene SVG. The model identifies a state
change, a captured expectation, a candidate input, a current-state reason and
a refused consequence. It declares comparable owner-state image encodings and
a comparison image for the checker.

=modules/d2/ascent-composition.ss= independently derives five =Near= constraints,
one state =Compare=, one =Check=, and the fact that the current-head reason is
=NonSequential=. It derives important-route needs and native solver preferences.
A state comparison gets stronger shortness/straightness preferences. The native
SDK/ELK then computes positions and paths from actual font measurements.

The Module refuses whole-scene artwork. The driver also refuses object images
that embed scene-node, scene-edge or explanation scopes. The old hybrid case's
scene SVG and handmade region/settings route have been retired from selection;
local state encodings remain ordinary model choices.

* Curiosity-driven reconstruction

The earlier zero-request picture was rejected by the reader: identifying the
fields did not make the mechanism vivid or invite investigation. That rejection
remains bound to its actual image in =readings.ss=.

The new composition infers =Divergence(captured,current,request,check)= from the
source-qualified capture, change, input and reason relationships. Its six open
=Explore= questions ask the current model to consider an initial expectation,
a discoverable change, a retained copy, a challenging clue, an experiment and
a misleading metaphor. No case identity or generation value occurs in those
rules. Removing the capture edge removes this inquiry even with unchanged art.

The model's proposed visual explanation is a fork: the live record turns after
a deadline while the request retains its saved tag; the two branches meet in an
inspection lens, where equal policy strokes coexist with unequal version tags.
The refusal is shown as a stopped update with a separately saved receipt. These
are local explanatory object/action illustrations. Native SDK/ELK still owns
the whole-scene positions and routes; no scene SVG or dedicated TS layout was
introduced. The snapshot metaphor stands for the frozen expected generation
and digest, not a claim that the command copies all policy bytes. A matching
tag alone would remove this mismatch, not establish every admission condition.

Supplying =representation.action= is a proposal, not evidence that it is
perceptible. The rules keep all six inquiry questions after descriptions are
supplied. Actual image reading must record what attracts attention, what could
be investigated, and what remains unclear; only a learner response could supply
independent evidence of that learner's curiosity or understanding.

The first reconstruction was actually viewed and rejected in part: the lens
rim crossed labels, the raised stop arm suggested passage, terminology still
presumed prior knowledge, and a long consequence tail wasted space. Those
image-bound findings reopened requests. The Module now derives a check and
terminal-consequence neighborhood; the model lowers the stop arm, separates
labels from the lens and uses the local property name =version tag=.

A further actual reading showed that native cross-hierarchy layout ignored the
child-direction preference. The module now selects native SIMPLE placement for
a detected split/rejoin, retaining NETWORK_SIMPLEX for other structures. The
incoming neighborhood padding leaves room for both evidence paths without
relaxing the existing route bound. Rejected second and third reconstructions
are retained under ignored output directories.
