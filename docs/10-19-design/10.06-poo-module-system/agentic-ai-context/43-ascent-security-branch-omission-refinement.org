* Research problem: security inference under bounded Context projection

Security investigation in an Agentic AI control plane faces a fundamental
tension:

- Core security inference invariants require preserving competing hypotheses,
  evidence lineage, active contradictions and open questions, evaluating every
  proposed investigation branch against every hypothesis, and refusing to turn
  missing-claim counts or hypothetical model fit into likelihood rankings,
  historical attribution or effect authority.
- At the same time, [[file:41-epistemic-consolidation-governance.org][Slice 41]] permits bounded working projections to select a
  proper subset of undefeated hypotheses when an explicit
  =OmittedAlternativesReceipt= is attached (=claimsExhaustive = false=).

Without an explicit coupling law between =OmittedAlternativesReceipt= and ASCENT
branch admissibility, an Agent viewing only the projected subset $\{H_1, H_2\}$
could conclude that a high-impact remediation action is safe across "all visible
hypotheses" while overlooking catastrophic collateral damage under an omitted
benign hypothesis $H_3$. This slice resolves that coupling and establishes a
machine-checked abstraction refinement ($\alpha$) from Lean to Quint following
the methodology of [[file:38-gitops-library-refinement.org][Slice 38]]. No Scheme code is touched.

* Concrete incident-investigation ORG case

Anomalous outbound egress and a modified configuration digest are observed in
Worktree =wt-incident-43=. Three competing hypotheses remain live in Temporal
Causality:

- $H_1$ (=h1_ci_key=): compromised CI token; 1 missing claim, challenged by
  active network-policy defeater $D_1$ (retained in the non-droppable kernel).
- $H_2$ (=h2_webhook=): confused-deputy webhook replay; 3 missing claims, high
  hypothetical model fit against payload logs, undefeated.
- $H_3$ (=h3_benign_canary=): scheduled canary rollout; 2 missing claims,
  undefeated, *omitted from the current tight working projection* with
  =OmittedAlternativesReceipt(omitted={h3_benign_canary}, claimsExhaustive=false)=.

* Semantic obligations and Lean-to-Quint refinement

** Relational obligations for ASCENT branch evaluation

Let $\mathcal{H}_{\mathrm{proj}}$ be the projected hypotheses and
$\mathcal{H}_{\mathrm{omit}}$ be the omitted live hypotheses recorded in
=OmittedAlternativesReceipt=. Every proposed branch $b$ must satisfy four laws:

1. *Complete projected matrix evaluation*:
   $\forall h \in \mathcal{H}_{\mathrm{proj}},\; (b, h) \in \mathrm{EvaluatedMatrix}$,
   with all active defeaters preserved.
2. *Anti-shortcut invariance*:
   $\mathrm{usedMissingClaimLikelihood} = \bot$ ($|M(H_1)| = 1 < |M(H_2)| = 3$
   never ranks $H_1$ above $H_2$ for authorization) and
   $\mathrm{usedHypotheticalFitAsAuth} = \bot$ ($\mathrm{Fit}(H_2)$ never
   establishes $\mathrm{AuthenticatedAttribution}(H_2)$ or grants $B_2$).
3. *Asymmetric branch gating under =OmittedAlternativesReceipt=*:
   - A *read-only discriminating branch* ($B_1$) requires complete evaluation
     over $\mathcal{H}_{\mathrm{proj}}$ and an active read-scope grant; it
     remains admissible when $\mathcal{H}_{\mathrm{omit}} \neq \emptyset$ so the
     investigator can gather discriminating observations or re-admit $H_3$.
   - A *destructive or high-impact remediation branch* ($B_2$) requires
     $\mathcal{H}_{\mathrm{omit}} = \emptyset$, $\mathrm{claimsExhaustive} = \top$,
     authenticated attribution, and an active remediation grant. Any non-empty
     =OmittedAlternativesReceipt= blocks $B_2$ fail-closed.

** Matrix antitonicity and heuristic-invariance algebra

In [[file:43-ascent-security-branch-omission-refinement.lean][43-ascent-security-branch-omission-refinement.lean]], pure matrix laws hold
over unbounded hypothesis lists without duplicating Quint's dynamic transition
state machine:

#+begin_src typst
$ (cal(H)_1 subset.eq cal(H)_2 and upright("SafeForAll")(b, cal(H)_2)) => upright("SafeForAll")(b, cal(H)_1) $
#+end_src

and perturbing =missingClaims= or =hypotheticalFit= on any hypothesis leaves both
=discriminatesPair= and =SafeForAll= algebraically invariant.
