* Worktree examples

The [[file:gitops-worktree/worktree.org][base Worktree]] uses
=context.gitops.worktree.v1=. Enabling WorkTrunk refines the Worktree
Contract family to =context.gitops.worktree.worktrunk= and keeps revision =1=.
The [[file:worktree/worktree.org][WorkTrunk Worktree]] declares the resulting
=context.gitops.worktree.worktrunk.v1= Contract ID. The root drawer holds the document ID,
Contract revision, and =GITOPS_PROJECT=, =GITOPS_WORKTREE=,
=GITOPS_SOURCE_CUT= and =GITOPS_WORKTRUNK=. Its placeholder evidence links to
[[file:worktree/design.org][design.org]], which points to
[[file:worktree/reference.org][reference.org]]. Each file keeps its own
=scheme :org-contract= block with a direct Org Elements expression.

Orgize validates each local Contract against the file that owns it. Its
Scheme =org-contract-block= form is also available for trusted, tangled
templates compiled as Gerbil modules. Task admission matches the selected
Worktree Contract ID and revision against the root drawer. The
Worktree namespace uses the registered source keys =A/worktree.org=,
=A/design.org=, and =A/reference.org=. The Scheme Task tests use the raw files
as input. The readable selector in a file link is its target =CUSTOM_ID=.
The receipt uses the target's local =ID= and the source generation admitted
by its Worktree Module.

* Evidence source profile

[[file:evidence-source.org][evidence-source.org]] is the executable source fixture and starter template.
[[file:consumer-context.org][consumer-context.org]] represents a Context consumer document. Its ID is a content anchor; SESSION_ID
is a reference to the independent Session owner. They have different roles.
Keep a document-local ID drawer and nonempty CONTRACT_ID / CONTRACT_REVISION
properties on the OrgFile. Selected content uses explicit local Property IDs.
The Provider qualifies each ID by its registered source identity. Different
sources may use the same local ID; duplicate local IDs in one source are refused.

Register original UTF-8 Org bytes at a monotonically increasing source version.
Changing content while preserving an ID requires a new admitted source version.
Retraction appends evidence; it never deletes the original bytes or proof.
Never put credentials in a template or treat a source block as executable code.

* Consumer boundary

The catalog's :ID: is an Org document anchor, not a runtime Session identity.
Session owners derive SESSION_ID with =agentic-ai-lab-session-identity= from
their persisted namespace/creation key. Context does not regenerate that ID
when source bytes change. A binding digest separately includes Session scope,
Query result and source/Contract versions. Runtime consumer documents may use
=SESSION_ID= and the existing detached =receipt-ref= / digest for binding
evidence. No second Session identity or Session-binding registry is introduced. Do not embed a binding's own hash in the source bytes being hashed.
Template placeholders do not constitute an admitted runtime binding.

Author ordinary Query values with AgenticAILabQuery and the existing GQL POO AST.
The initial Provider supports the existing bounded single-node GQL Scheme
slice over property-bearing Org Elements. Context Session tasks additionally
require document roots or open headline anchors accepted by the existing runtime
Context profile. Unsupported paths, incomplete results and unbound source cuts
are refused. GQL, Org Contract, ASCENT proof, authority and Session are distinct
contracts; none is a substitute for the others.

* Layered GitOps topology and inline multi-agent governance

[[file:governance/topology.org][governance/topology.org]] (=context.gitops.topology.v1=)
defines Layer 1 project-wide architecture and entry routing
(=PROJECT_ID=, =GITOPS_SHARED_STORE=, and component headlines with
=ARCH_COMPONENT= and =ENTRY_SOURCE=) so Agents locate governed Org sources
through GQL without blind search.

[[file:governance/work.org][governance/work.org]] (=context.governance.work.v1=)
defines Layer 2 inline multi-agent governance where each =:ID:= section carries
an immutable governance header (=:AGENT_ID:=, =:REVIEWER_AGENT_ID:=,
=:TASK_ID:=, =:ARCH_COMPONENT:=, =:DEPENDS_ON:=) and an Agent-editable body
admitted through =context-governance-host= single-use tokens and structural rebase.

[[file:seed/session-seed.org][seed/session-seed.org]] (=context.session.seed.v1=)
provides the minimal organic session seed. Instead of pre-baking static ADR or
execution-plan templates, =ASCENT= deductive rules inspect =Org Elements= AST
facts and user-case signals to derive triggered structural facets for Flash
synthesis, =L0..L3= progressive disclosure spans, and two-stage AST/Flash
repair. See [[file:../../../../docs/10-19-design/org-elements-gql-context-design.org][Org Elements, GQL, and ASCENT Progressive Context Design]].
