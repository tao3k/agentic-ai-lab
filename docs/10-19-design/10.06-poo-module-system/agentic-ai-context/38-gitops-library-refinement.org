* Business subject

The subject is Lab's =agentic-ai-lab.gitops.create= revision 4. Given a Policy,
previous evidence, a receipt and current observations, do the actual Scheme
operations and the Quint specification make the same decision and preserve the
same evidence? Package installation, dependency resolution, compilation and
upstream Module System behavior are not tested by this relation.

The concrete operations are the public =bind-working-copy-policy=,
=select-working-copy=, =admit-working-copy-receipt= and
=refresh-working-copy-evidence=. Both suites import the shared
[[file:../../../../t/yanxu/interface.ss][t/yanxu/interface.ss]] dependency facade and read =(.get Lab gitops)=.
The facade uses the root init's existing selection. It declares neither a new
Loader nor another test directory or suite list.

* One readable business history

The [[file:../../../../t/yanxu/modules/gitops/refinement-test.ss][Scheme suite]] executes this history with actual POO values. Quint emits
an expected successor for each step from the [[file:38-gitops-library.qnt][same pure library model]] imported
by the protocol. Every row compares both results, rather than asserting a
separate expected answer independently in each language.

| Event | Observation or receipt | Scheme and Quint current result |
|-------+------------------------+---------------------------------|
| original-binding | A matching fresh r1 receipt returns /old | New admission; current binding /old |
| duplicate-changed-path | Another r1 receipt claims /returned | No new admission; preserve /old and append the original receipt |
| revoke-authority | Current authority becomes false | Withdraw current use; retain receipts and spent r1 |
| restore-authority | Authority becomes true again | Remain withdrawn; observation restoration does not revive a binding |
| late-spent-receipt | r1 is redelivered after restoration | Remain withdrawn; retain the late receipt |
| fresh-request | A fresh matching r2 receipt returns /returned | New admission; current binding /returned; both requests stay spent |
| replace-policy-object | An equal-shaped but distinct Policy is selected | Withdraw current use; do not transfer a binding to that object |
| restore-policy | The original Policy is selected again | Remain withdrawn |
| late-duplicate-after-policy-restore | Spent r2 claims a different path | Remain withdrawn; preserve history |

These are evidence interpretation operations. No Git, process, Worker or
concrete provider is executed. Current authority, fence applicability and receipt
custody are supplied observations; interpreting them does not authenticate them.

* Relation and commuting step

** Derivation, replacement and historical applicability

| Business rule | SysML requirement | Scheme authority | Quint projection / paired case |
|---------------+-------------------+------------------+--------------------------------|
| Bind an Org leaf under a parent Policy | policyDerivation | bind-working-copy-policy captures source/anchor/revision and intersects allowed capabilities | bindPolicy; projected original/replacement/rebound Policy values |
| Preserve named higher-order behavior | policyDerivation | Derived POO object inherits select-provider; explicit parent refinement may replace it | Policy.selector identity; inherited selector checked after Org rebinding |
| Derive again without restoring removed capabilities | capabilityRestriction | The supplied derived parent remains the bound; P05 checks the next child | restrictCapabilities and nested bindPolicy |
| Select a replacement Policy | policyReplacement | Caller passes the new Policy to refresh/admit; current-use requires exact active Policy identity | replacementTest steps 1 and 4 |
| Change a Policy definition while keeping the Org cut | policyReplacement | Caller supplies a new semantic revision; late old-revision receipt is retained without adoption | replacementTest steps 2/3 |
| Bind a new Org cut | policyDerivation and semanticAdmission | New source/anchor/revision are captured; old source evidence is retained but refused for current use | replacementTest steps 5/6 |

The seven-step replacement trace begins with Policy A, derives a Git-only named
strategy at revision v2, and then rebinds that derived Policy to a changed Org at
v3. It compares the complete Policy values as well as the evidence successors.
The original parent stays unchanged. An old pending v1 receipt is refused under
v2 even when the Org cut is unchanged; a later fresh matching receipt is adopted.
After Org rebinding, the old Org/v2 receipt is refused and a fresh Org/v3 receipt
is adopted. Historical receipt objects and spent identities remain intact.

Revision labels are supplied by the Policy author. The library checks nonempty
labels and equality; it does not infer semantic equivalence of arbitrary Scheme
procedures. Selecting an equal-shaped new object withdraws automatic current use.
Historical evidence is not declared false: explicit adoption still evaluates
its source, revision, anchor, request, provider and supplied current facts.

** Evidence relation

Let =alpha= map a concrete evidence object to:

- the ordered original receipt identities;
- ordered spent request identities;
- active Policy object identity, active request and active provider;
- current returned binding;
- newly =admitted?= and currently =accepted?=.

The finite witness uses named identity classes for Policies, requests, providers
and paths. Receipt names are backed by a separate identity condition: every
successor retains the exact original POO receipt objects in order, and its
binding is the original incoming or retained binding object. Equal field values
alone do not satisfy that condition.

For every admitted input in the named partition, R01 checks:

#+begin_example
alpha(Scheme.receive(c, receipt, current))
  = Quint.receive(alpha(c), abstract-input(receipt, current))
alpha(Scheme.refresh(c, current))
  = Quint.refresh(alpha(c), abstract-input(current))
#+end_example

It also compares the published Contract's actual source/admission/retention
predicates with the corresponding Quint results. Input abstraction uses the
actual equalities and observations: source fields, revision, request, provider,
anchor, freshness, Boolean authority/fence/custody/execution and outcome/binding.

[[file:37-worktree-gitops.qnt][The protocol]] now calls these same Quint =receive= and =refresh= functions.
Its =libraryProjection= invariant relates current use and historical acceptance
to the embedded evidence state. =boundPath= remains the historical accepted
path; =evidence.binding= is the current binding and becomes absent on withdrawal.
The finite protocol allows one original delivery and one redelivery. External
source/authority changes include the consumer's refresh of supplied observations;
they do not make Scheme observe a filesystem automatically.

* Finite coverage and falsification

The [[file:39-gitops-refinement-witnesses.qnt][Quint witness source]] enumerates concrete input representatives by ID.
=max-samples=1 evaluates every row in each partition. The large partitions
emit ordered lists, avoiding structural hashing of nested Evidence records.
The Scheme consumer checks the partition size and unique, in-range IDs.

| Partition | Cases | What is compared |
|-----------+-------+------------------|
| Admission facts and initial/spent state | 16,384 | All fourteen Boolean fact combinations, full successor and published predicate |
| Occupied current binding | 16,384 | A fresh or spent request may admit, preserve the old use, or withdraw it |
| Previously withdrawn binding | 16,384 | Refused/spent evidence cannot revive current use |
| Retention facts | 256 | All eight combinations, full refresh and published predicate |
| Source equality | 64 | All five field combinations on both current and receipt source cuts |
| Provider correspondence | 4 | Selected-and-allowed, other allowed, unknown, and selected-but-restricted |
| Business history | 9 | The named sequence above, including original object lineage |
| Policy specialization/selection | 64 | Parent/local capability intersection, preference and availability |
| Policy and Org replacement | 7 | Derived Policy values, old revision refusal, new revision admission, Org rebinding and old source refusal |

The current source defines 49,556 paired cases. Eight deliberately corrupted successor fields
must be rejected. Two additional controls reconstruct receipt/binding objects
with identical scalar projections: the identity condition must still reject them.
The protocol's seven unsafe variants remain separate required counterexamples;
a compiler error or timeout never qualifies one.

This is an executable bounded refinement relation. The examples cover five
request names, two available capabilities plus an unknown provider, five Policy
identities, finite history prefixes and Boolean input partitions. It is not an
unbounded theorem about arbitrary Scheme callbacks, all histories or all provider
names. Malformed inputs lie outside the relation's typed domain and are refused
by the existing C02/C03 tests. Physical observation, authorization, execution,
persistence and global deduplication remain external responsibilities.

* Run and read the evidence

#+end_src

The directory must be new. The maintained Just entry runs the original Contract
suite and R01 in one aggregate 120-second, default 2-GiB Scheme process. Quint
witness generation has a 30-second wall limit and a 1-GiB Node heap. The Scheme suite
prints named =SCENARIO-OK= rows and writes original ITF witnesses, =quint.log= and
=receipt.ss= to the local artifact directory. Source and witness hashes must remain
unchanged during the comparison. The receipt records bounded correspondence;
it does not claim an unbounded source proof or Quint catalogue closure.

The repository's existing =just test-lab-layout= is an independent ownership gate.
It is not part of refinement, and this suite contains no package-management or
dependency-version probes. The parallel facade/Core version mismatch is recorded
separately in [[file:37-worktree-gitops.org][37]], without re-testing upstream package management or adopting
its uncommitted changes.
