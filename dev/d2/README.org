* Separation

[[file:../../modules/d2/README.org][modules/d2]] owns POO Diagram values, ASCENT Scheme rules and D2 projection.
This directory owns only development selection, sample inputs, launch/build
adapters and teaching/rendering views. The Context system remains the underlying
information/relationship owner; the Module's optional Context profile is a
bounded example, not a second runtime authority.

=init.ss= selects the published Module through the existing Module loader.
=build.ss= uses its standard source-closure mechanism. =drive.ss= calls the
public scope and serializes its result. It contains no rules or graph traversal.

* Run

Requires the project Gerbil environment and Bun >= 1.3.11.

#+begin_src sh
# From the repository root: Scheme/ASCENT -> D2.
just d2-export
just test-file t/d2-module-test.ss
just test-file t/context-window-ascent-test.ss
just test-d2-rules
just test-d2

cd dev/d2
bun install --frozen-lockfile
bunx playwright install chromium
bun run check

# Drives the Module, then renders its two actual inference results:
bun run ascent

# Explanatory illustrations, preserving the same visual quality objective:
bun run temporal
bun run evolution
bun run window
bun run session
#+end_src

=ascent-early= has one visible supporting observation and a review candidate.
=ascent-later= includes a late counterexample, retains both hypotheses, reports
the conflict and no longer marks that method as a review candidate. The D2
nodes/edges/statuses come from ASCENT Scheme. TS uses SDK model classes only
to select drawings/captions; it does not redo the inference.

* SDK and rendering boundary

The fixed rendering dependency is
https://github.com/hardenedlinux/deterministic-engineering/tree/1fe20380441a0cd85055695c2adcc55ce699a369/packages/render
with its dependency closure pinned in =bun.lock=.

- D2 artifacts go through the official D2 SDK via upstream =compileModel=.
- Existing SysML views go through the OpenSysML TypeScript SDK and upstream
  =captureOpenSysMLView/projectOpenSysMLView= directly.
- Upstream =composeFigure/composeDiagram/exportFigure= owns browser measurement,
  ELK scene layout and vector export. No custom JSON view model/config is added.
- This is presently a file handoff, not C ABI integration. The
  [[file:../../modules/d2/README.org][Module README]] states the direct-runtime boundary and remaining work.

Each example produces local =.svg=, preview =.png=, offline =.html= and
=.receipt.json= under ignored =output/=. D2 source is the Module's output format;
the JSON receipt is diagnostic output, never another editable semantic graph.
Captured source changes during rendering refuse export. Receipt source inventories
are provenance capture, not a build-role registration list.

* Visual standard

All figure text is English. Start from what a newcomer should understand and
choose representations for the current scene, object state and distinctions.
The same POO Object need not have the same picture in different explanations;
retaining an expression can also help track the same object across views. Keep
word load low and make relationships visually explicit. Do not freeze that
objective into one card template, panel count, icon taxonomy or layout algorithm.

The explanatory =temporal/evolution= SVGs are explicitly authored compositions.
They explain proposed Context semantics and are not claimed to be generated by
ASCENT. The =ascent= examples exercise ASCENT-driven graph selection with an
illustrated teaching compositor; their relationship endpoints and status classes
come from the Module, while pictures and routing express a selected explanation.
They are not a framework-wide fixed layout. These receipts are not interchangeable.

The Module also exposes reader questions/review relations. A model can ask what
an inexperienced reader needs to understand, propose prerequisite explanations
and critique an actual image. ASCENT derives gaps and revision obligations over
those observations. The browser does not infer pedagogy from pixel geometry,
and model critique does not stand in for observed learner understanding.

The 12px readability gate remains unchanged. English illustrations currently
use the embedded Inter fonts under OFL-1.1. Visual inspection complements the
upstream checks; standalone illustration positions are not checked as ELK scene
geometry. No shrinking/retry fallback is introduced to pass a failed gate.

* Native design sources in the default model environment

=bun run window= reads =32-time-window-context-evolution.org= and its SysML
companion. =ContextWindowFigures::evolution= supplies the native SDK view: eight
parts, their teaching-content attributes and ten connections. The SDK's =BeginnerPerspective= symbol supplies
current reader questions, without enumerating their names in driver code.
The final POO boundary projection goes to =design.ss= and the public D2 scope;
the Module emits D2 and outstanding authoring requests. =window-design.ts= is
one model-authored illustration of that selected view, not a framework rule set.

Org/SysML content hashes bind the Context source cut. The compositor source
binds the candidate asset. An actual render automatically contributes its PNG
digest and triggers another Module evaluation. Successful export never fabricates
semantic review approval. The surrounding model inspects the actual image and
returns prose findings, required distinctions, located quotations and depiction
concerns through =examples/window-evolution/readings.ss=. The host measures text
anchors/rectangles; =modules/d2= derives concrete explanation, illustration and
layout changes. No external
model endpoint, independent Agent process or fixed model-stage loop is needed.

The output files are =output/window-evolution.{svg,png,html,receipt.json}=,
the inferred =output/window-evolution.d2=, =output/window-requests.org= and
=output/window-findings.org=. =output/window-evolution.anchors.json= is a measured
export diagnostic, not an editable semantic model or a review verdict.
The =output/window-source.ss= file is a generated POO boundary projection of
the SDK result, not a hand-maintained graph or another JSON design model.
The export captures its pre-render input snapshot; the live Context projection
is then advanced with the measured image digest and anchors. =design.ss= verifies
PNG bytes before invoking inference. The current model continues to address the
derived changes and inspect the resulting image; successful export does not
stand in for that work. [[file:examples/window-evolution/README.org][The image-reading example]] retains the raw findings
and reports how the two questions changed the picture.

* Reuse with another existing Org/SysML design

The [[file:examples/hybrid-allocation/README.org][hybrid allocation case]] reads the existing 28-hybrid Org and SysML design
without modifying them. It supplies =case.ss=, =readings.ss=, a native view and
local SVG assets. There is no corresponding =hybrid.ts= or special compositor.

#+begin_src sh
# From the repository root:
bun dev/d2/reuse.ts --case dev/d2/examples/hybrid-allocation/case.ss
# After the current model has read the image and returned located findings:
bun dev/d2/reuse.ts --case dev/d2/examples/hybrid-allocation/case.ss --evaluate
#+end_src

The same generic adapter accepts another POO case path. =modules/d2.scene=
selects the teaching view; the standard SDK compositor and ELK handle positions
and routes. Case data chooses native ELK options, labels and image resources.
The adapter propagates those declared options through compound boundaries;
otherwise default child options can cause an unintended horizontal strip.
The final process handoff is JSON over stdout only, after POO inference, and
is never an editable JSON design model. Native SDK objects remain in memory.

The original 12px export gate remains unchanged. A rejected export exits with
failure and retains a separately named diagnostic PNG/HTML for actual model
reading. That candidate observation does not publish a qualified figure or
claim semantic review success. Rejected layouts remain in the local trace.

* Earlier model-host session

[[file:examples/time-window/README.org][Time-window session]] records actual model generation, image inspection and
feedback over three revisions. =author.ss= invokes the public =author= scope and
writes an outbox of ASCENT requests; =session-render.ts= only captures sources,
binds named SVG objects to D2 SDK identities, exports the model-authored surface
and verifies receipts. Example facts and assets live under =examples/time-window=.
Neither driver contains ASCENT rules, a stage transition table or image-choice
policy. This historical example retains explicit POO findings. The native design
path above uses the default surrounding model environment and does not reuse
these fixtures as live review-success results.

* Question-relative mechanism explanations

The reusable driver accepts source-qualified POO =teaching= proposals and a
=mechanism= value. The Module selects explanatory links, checks required
relationships and requested state-change traces, and reports structural gaps.
The compositor projects the selected relation graph through the existing
=composeDiagram/graphFromModel= APIs. Browser measurement and ELK calculate
positions and routing; native wrapping/model-order options are POO case data.
There is no design-specific TypeScript layout.

A qualification may be attached to the object it qualifies only through a
source-qualified, non-propagating relation. A causal relation cannot be hidden
as a note. A no-effect relation is shown as an explicit crossed statement at
its source, not ranked as a runtime transition; a propagating relation cannot
be declared a no-effect relation. The original native source trace remains
captured independently of these pedagogical views.

The upstream exporter produces vector SVG, PNG and offline HTML, keeps the
original text-size gate, and binds actual node/edge-label measurements to the
image digest. The current model reads the actual picture, traces its conditions
and returns natural observations and contrary findings. Request counts describe
the supplied inventory; they do not establish student comprehension. The
three-row gallery was rejected despite reaching zero requests, and that
negative evidence remains in the example's Context readings.

Whole-scene =artwork= is now refused; moving coordinates from TypeScript into
an SVG was not reusable composition. Teaching uses the selected objects, links
and native solver preferences inferred in =modules/d2/ascent-composition.ss=.
The generic compositor projects those preferences without naming designs or
deciding which relationship is a reason or a state comparison. Local object
artwork remains model-authored and cannot embed a complete explanatory scene.

=examples/policy-generation= reuses the existing Policy Transition Org and SysML
fixture. Its POO case has no regions, direction, layout options, route-needs,
coordinates or whole-scene illustration. The model supplies meanings, captions,
state encodings and local imagery, then reads the actual exported picture.
ASCENT infers comparison/check obligations, solver preferences, route needs and
reader-size requests. Native provenance and current-image/source guards remain
in force.

=examples/durable-task-source-case= reads an actual =durable-owner.ss= source
change through existing Durable recovery, source-command and Task designs.
The generic driver renders its native SysML relations and local object/action
illustrations. The current model reads the resulting image and supplies
image-bound findings; this case performs no test or fault injection.

* Durable Module extension and recovery views

=examples/durable-feature-composition/= reads section 18 and the proposed
Module/Feature parts in the existing section-19 SysML package. The existing
Core Feature System owns contributions and contract binding; the diagram does
not claim the provider extraction or extension integration is implemented.

=examples/durable-owner-recovery/= reads section 19's existing committed-readiness
recovery boundary. A replacement owner reconstructs from retained decisions and
keeps the original unresolved Attempt. The images explain object relationships;
the generic driver does not execute verification cases or runtime tests.

Both cases supply source-qualified POO meanings and local object/state artwork.
They contain no coordinates, solver options, fixed regions or scene artwork.
ASCENT derives comparison, retained/change investigation and native composition
constraints; actual model readings are bound to each exported image. These
views supersede the source-edit illustration for the requested architecture case.
