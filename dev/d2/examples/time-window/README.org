* Why these pictures

The window ribbons share an event-time scale and explicitly name their known
cuts. Two labeled time marks explain late knowledge without asking the reader
to infer what an unlabeled clock means. A build conveyor depicts observations;
stacked generated parts suggest one possible cause; disconnected incompatible
plugs make another cause understandable without ABI vocabulary. The repeated
stack tracks the same hypothesis across two views. An open field notebook keeps
a method alongside scope and counterexamples rather than portraying automatic
promotion to an authoritative book. These are model-authored choices for this
lesson, not global object-kind-to-image rules.

This reproduces artifacts and re-evaluates recorded observations. A fresh image
inspection must be performed by the model host when starting a new review.
If rendering produces different pixel bytes, old findings cannot approve those
new bytes; inspect them and add new observations instead of editing old hashes.
=author.ss= verifies the proposal/render/observation byte hashes before and after
inference. The TS receipt verifier also checks captured semantic sources. A
deliberately altered PNG was rejected by the verifier during this session.

To continue, introduce questions, candidate expressions, new view revisions or
other model observations as POO facts. Invoke =just d2-author <revision>= to read
the current outbox. The host decides how to address those requests and may use
ordinary code-native SVG authoring and image-view tools, or another provider.
There is no serialized visual JSON model and no hidden model-stage loop in TS.
Receipt JSON is export provenance only. Passing these finite checks establishes
neither actual pupil comprehension nor production Context/Durable integration.
