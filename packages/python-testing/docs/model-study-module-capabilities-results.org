Four responses were readable =answer= data, and one was exact. The other
three were explanatory prose, despite the request in the source comments
to return one datum. The two incomplete module-source responses reached
the 512-token output cap before an answer. The completed fragment response
also included prose and a wrong =(answer ())= in a code fence. The native
scorer correctly rejected all three as non-datum output. This is an
observed prompt/format failure as well as an answer failure; it does not
show whether a short answer-only prompt would yield a correct module result.

* Bounded interpretation

The explicit API-contract case produced the exact three-row answer. The
pure Scheme case omitted =(1 8)=; withdrawal and negation/count also
returned wrong rows. One call per case cannot estimate reliability. The
result does not establish general Scheme competence, general incapacity,
or an internal reasoning mechanism. A targeted follow-up may put the
answer-only instruction after the module source and calling program,
keeping source and answer checking otherwise fixed. It needs a new exact
preview and separate call authorization.
