#+title: User Module, Profile and Scenario Library
#+language: en

The root [[file:../init.ss][init.ss]] selects these sources through =yuanxu!=.
Profiles are ordinary modules mounted under =Profiles=; no independent Profile
or Registry loading API remains. See [[file:CONTRACT.org][the source-role contract]].

* Profiles

- [[file:profiles/langchain/interface.ss][LangChain]]: linear memory, prompt, model and parser policies.
- [[file:profiles/langgraph/interface.ss][LangGraph]]: typed state, routing, bounded loops and explicit handoff.
- [[file:profiles/crewai/interface.ss][CrewAI]]: agent/task/crew/flow relationships and guardrails.
- [[file:profiles/tool-calling/interface.ss][Tool calling]]: permission, arguments, cooldown and receipt boundaries.

Each module has =types.ss=, ordinary defaults in =config.ss=, domain projections
in =objects.ss= and one declarative =interface.ss=. =Profile.= reads final Config;
=profile= is admitted by the existing SemanticModuleContract. Namespace leaves
are the configured POO objects; there is no additional scope facade.

* Scenarios and ordinary configuration

[[file:scenarios/developer/interface.ss][Developer]] publishes its ordinary configuration,
inert domain preview and declaration diagnostics through the same module
protocol. [[file:custom/my-module/interface.ss][The custom module]] has the same roles.
The domain intent rows in Developer's Config are preview inputs, not another
module-loading graph. The root alone selects modules.

[[file:config.ss][The control-plane composition]] consumes published Profile values.
The existing LangChain, LangGraph, CrewAI and tool-calling Scenario Case sources
remain pure domain examples; acquiring a semantic value and composing its fields
does not select or activate another module. Native POO assignment, inheritance
and functional slot refinement own object changes.

* Reproduce

From the repository root, use =just test-file t/user-interface-root-config-test.ss=,
=just test-file t/yanxu/Profiles/sandbox/profile-module-test.ss= and the domain Contract suites.
Use =just test-root= for the official product test inventory. Build preparation
and test execution are separate; namespace access does not run std/make or Ops.
