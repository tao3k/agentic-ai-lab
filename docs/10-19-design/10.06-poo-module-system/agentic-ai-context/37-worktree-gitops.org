* Architectural subject

The subject is =modules/gitops= in Agentic AI Lab. Its public interface is a
Yuanxu Module whose exports are POO objects and named pure functions. AITIA,
Marlin and other applications are downstream consumers. The library neither
imports them nor supplies their execution runtime.

The [[file:37-worktree-gitops.sysml][SysML v2 architecture]] defines two ports: =PolicyPort= accepts a parent
Policy and Org cut and returns specialization/selection; =EvidencePort= accepts
current facts, a receipt and previous evidence and returns successor evidence.
A consumer uses their conjugates and supplies its own execution owner. Physical
execution occurs outside =LabGitOpsLibrary=.

* POO composition and open capabilities

=working-copy-policy= is a POO prototype. =bind-working-copy-policy= parses the
selected Org text with the existing Orgize Element graph, requires one unique
anchor and a policy revision, and derives a Policy with =.cc=. Space-separated
=GITOPS_ALLOWED= names restrict the parent capability set. =GITOPS_PREFERRED=
names one declared capability; preference cannot add authority or availability.

A named =select-provider= function is inherited or overridden through normal
POO composition. Its return is checked against both the derived allowed set and
the consumer-supplied availability object. New capability names use the same
slots; concrete package names and native execution types are not registered in
Lab. Each consumer can derive its own Policy and maintain its own evidence state.

* Contract and conditional interpretation

The published =create-contract= has identity =agentic-ai-lab.gitops.create=,
semantic revision 4 and =effects-owner= equal to =downstream-provider=. Its
predicates are the actual functions used by Scheme evidence transitions.

The =inputs= slot publishes real =define-type= descriptors, not symbolic type
names or another schema evaluator. Public operations call =validate= at their
input boundaries. Malformed POO inputs raise a Type admission error and produce
no successor state. Contract-compatible refusals remain receipts in successor
evidence. This separates a malformed envelope from an observation whose semantic
applicability is being evaluated.

| EvidenceState current use | active-policy, active-request, active-provider, binding, admitted?, accepted? | Retain only under the exact active Policy object, request and provider, with current source/revision/grant/fence | E01, E03, E05 |

Policy Type admission checks the selector/capability surface; binding additionally
qualifies the Org source and anchor. Receipt Types admit absent or empty-path
bindings as unusable observations; semantic admission refuses them while keeping
their receipts. Non-POO bindings and non-Boolean authority/custody facts fail Type
admission. Shape admission never authenticates these caller-supplied facts.
Evidence-state Type admission checks each retained receipt and spent request;
an optional branch is a String when present. It does not establish historical
authenticity or prevent a caller from forking persistent state values.

The source correspondence includes project, Worktree, Org path, selected text
and observed Git HEAD. Receipt acceptance additionally requires matching policy
revision, Org anchor and request, unspent request identity, current authority,
=fence-current?=, valid custody, execution, an allowed provider, an applied
outcome and an actual binding from the provider selected for that request. These
are supplied facts, not grants synthesized
from an Org declaration or a success status.

=admitted?= reports a new acceptance; =accepted?= reports current use. Duplicate
delivery may retain a valid current binding without admitting again. Refresh
withdraws use when applicability changes, retaining receipt history and spent
requests. Restoring observations after withdrawal does not automatically revive
that binding. The caller threads the returned state; these are persistent
functional values, not a global execution or durable deduplication service. A
later fresh request can replace current use while retaining both original
receipts. An unusable redelivery cannot substitute its path for the previously
accepted binding.

* Bounded protocol model

[[file:38-gitops-library-refinement.org][38: the actual library refinement relation]] defines the commuting Scheme/Quint
step, ordered history and object-identity conditions, and a readable nine-event
business history. Its maintained Scheme check compares both implementations on
the same inputs; package-management behavior is outside that check.

[[file:37-worktree-gitops.qnt][The Quint model]] abstracts two provider capabilities, one captured source and
Policy cut, one request and one returned receipt. It separates composition,
consumer projection, owner admission, execution, evidence return and semantic
consumption. Composition cannot silently recapture a later source cut.

The guarded protocol checks dispatch safety, result applicability, actual
returned binding and once-only acceptance. The six original deliberately unsafe wrappers
retain dispatch, result, foreign receipt, intended-path substitution, duplicate
and capability-widening counterexamples. A seventh control accepts an allowed
but unselected provider's receipt and must also fail. The positive wrapper has
sixteen deterministic traces, including mutation before composition and a
provider mismatch refusal. POO Type admission excludes malformed input shapes
before this typed protocol abstraction. Multiple requests and active POO object
identity remain outside the protocol's single-request bound; they are covered
by E03/E04 and the paired library-kernel business history in 38.

This is a conditional finite protocol model. Its external owner checks are
assumptions to be discharged by whichever downstream adapter is selected. It
does not prove physical execution, arbitrary file races, persistence, all
providers, source refinement or distributed exactly-once behavior. Scheme
Contract tests are direct library evidence, separate from Quint source/typecheck/
predicate receipts. No new code generator or Python orchestration owns semantics.
