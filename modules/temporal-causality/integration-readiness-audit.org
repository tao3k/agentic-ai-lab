* IFC findings against RFC 91

RFC 91 requires restrictive Context composition, preserved provenance, typed
labels/flows, leases, redaction conflict handling and declassification linked to
Authority and Evidence. =src/semantic/organization-bundle.ss= currently models
context projections as agent ID plus visible symbols. =facet->canonical=
includes constraint symbols in identity; =bundle-validate/unsafe= checks child
visibility against parent visibility. These operations do not interpret general
constraint symbols as a label algebra or a declassification policy.

No full IFC gate follows from that subset check. The Temporal family wire,
source snapshot and selection receipt do not carry an admitted information-label
or declassification receipt. A local selection grant is not an information-flow
permit. Before exporting restricted source or model output to another principal,
the integration needs an explicit POO-owned flow decision bound to content,
source revision, principal, destination, policy and expiry. Negative gates must
cover incomparable labels, constraint widening, lost provenance, expired leases,
unauthorized downgrade and source changes between flow check and use.

* Rust integration decision and acceptance order

The basic library is ready for a bounded Rust read-only integration. Full engine
closure and model acceptance are not prerequisites for testing that transport,
but the consumer must preserve the profile's limits. General causal conclusions,
current authorized selection, IFC-controlled export and business effects are not
yet qualified for this integration.

** R1: Consume the owner seam and original receipts

Migrate MRR Data's immutable MRR pin to a reviewed revision containing
=mrr-property-source=, regenerate the lockfile and replace duplicate compilation,
binding and candidate admission orchestration. Preserve original compilation,
query, catalogs, snapshot, root and result receipt; physical execution stays in
MRR Data. Existing source-drift, wrong catalog/generation, transfer and row-limit
negative cases must continue to pass under that exact dependency head.

** R2: Implement one POO-owned Rust runtime consumer

Use =bindings/runtime-c/include/agentic_ai_lab/semantic.h= rather than a Python bridge
or a new Rust classifier. The native lifetime is process-global, thread-affine
and terminal on close. Open/call/release/close on one dedicated OS owner thread
with a bounded queue. Do not dispatch native calls on arbitrary Tokio workers,
close after each request, send native pointers across threads or reopen after
terminal close. Verify artifact digest and operation/profile before calls.

Initial scope: lens solve/observe and finite-family classify/observe. Expose
source registration as a separate trusted host capability, never a model tool.
A Rust publication binding is a later gate over the same typed C store contract;
it cannot replace POO admission with caller-provided basis JSON.

Acceptance: installed Rust consumer/native artifact; differential C/Python/Rust
results for two vocabularies; unknown/partial/budget/stale binding; queue bounds,
wrong-thread and lifetime guards; no bare model output admitted; genuine progress
watchdog. Add a separate real DeepSeek read-only family tool batch against the
new artifact, preserving historical failed predictions and exact profile scope.

** R3: Connect MRR output to Temporal candidate exchange

Export original typed rows and original MRR receipt together. Retain parser
source/grammar, query binding, catalog/snapshot/result digests and completeness
claim; admit an explicit mapping to Temporal source/cut/projection/policy.
MRR generation is a content-addressed semantic identity, whereas Temporal's
current host generation is a bounded monotonic integer. Preserve both and bind
the correspondence to the source owner; do not parse/hash/cast one into the other
or equate generation with event time. Unsupported Node/Relation/List values need
an explicit projection or rejection, not silent scalar coercion.

Negative gates: changed row under same receipt; reused result under different
query/root/catalog/generation; incomplete source inventory; foreign checker;
missing original parser receipt; ambiguous generation/cut mapping. Result shape
admission must not imply proof completeness, issuer authenticity or flow permits.

** R4: Close lifecycle and IFC gates before stronger publication claims

Add current-applicability verification after source/grant changes; durable proof
journal references that can be resolved and replayed; correction/retraction and
SCC stabilization; atomic verified permit fences; IFC flow/declassification
receipts bound to the same transfer/commit. Require general publication races
and recovery tests at their actual operational boundary. Do not infer these from
first-root CAS, abstract Quint, or a successful read-only model tool batch.

* Rust MRR optimization candidates and measurable limits

| Candidate | Concrete source seam / benefit hypothesis | Acceptance before optimization claim |
|-----------+-------------------------------------------+--------------------------------------|
| Remove duplicated owner logic | MRR Data property_source -> MRR property-source compile/bind/admit | Identical original receipts and negative controls; reduced duplicated code, no invented query identity |
| Cache compiled/bound queries separately | Immutable original source/compiler identity; query/catalog/semantic snapshot bindings | Every source/compiler/catalog/generation change misses; budget/policy/IFC scope cannot reuse a more permissive entry; bound cache bytes |
| Reuse immutable physical blocks | MRR Data CID restore and transfer caches | Byte/closure validation remains intact; generation and coverage remain bound; measure cold/warm bytes, latency and peak memory |
| Batch typed exchange, bound copying | MRR candidate rows -> POO supported wire projection | Enforce total bytes/rows/cells/depth before allocation; preserve canonical native digest separately; no partial result called complete |
| Incremental invalidation | MRR lineage impact + Temporal reverse-support plans | Complete support inventory and SCC gates first; then measure impacted work without skipping retractions or dual supports |
| Queue and cancellation control | Dedicated Rust native owner + MRR physical worker | Bound queue/memory/deadline, stop cancelled read-only work without unsafe native interruption; measure p50/p95 and contention |

These are proposed optimization experiments, not demonstrated performance gains.
Do not add another Temporal solver or causal authority inside MRR. The next
concrete integration slice is R1/R2 followed by R3; R4 gates stronger claims.
