* Scope and reading rule

This map records inspected repository designs, not new claims of their runtime
qualification. The user's direction is overall Agent Context management across
content, interaction history and short-/long-term knowledge, while Session
remains independent. Existing Org contracts supply the architecture; SysML
organizes their responsibilities and selected lifecycles.

Read explicit ownership/status/supersession sections before treating old paths
or examples as target architecture. The contracts are overlapping views, not a
chronological sequence in which every newer file replaces every older file.
Existing qualification receipts remain scoped to their own cuts and claims;
they were not rerun by this documentation change.

* Feature component and test ownership

Yuanxu owns Feature composition under =module-system/feature=. Maintained Lab
adapters import =:yuanxu/module-system/feature/interface= or a specific module
under that same namespace. Module authors declare their optional contributions
in their Module Interface; init selects =+memory= or =-memory=.
Core validates the final receiver against both its Core Type and selected Feature
Types, while source guards remain active across the declaration and callbacks.

The ordinary Core test inventory discovers =t/feature-*-test.ss=,
=t/feature-test.ss= and =t/module-feature-*-test.ss=. Lab's writer integration
uses =t/feature-bundle-v1-composition-writer-test.ss=. Run the existing entries:

#+begin_src sh
just test-file t/feature-bundle-v1-composition-writer-test.ss
just test-file t/yuanxu-context-memory-downstream-test.ss
just test-file t/yuanxu-deployment-downstream-test.ss
#+end_src

The package gitlink selects the Core revision used for this qualification.
Gerbil builds that revision and its declared dependencies before the tests.
Interpreted source tests using older compiled publication Types are a different
cohort and do not qualify the migrated Interface.

* Corrections to the first discussion draft

The first draft incorrectly presented static dependency direction as an open
choice for an additional upper manager. Session owns its descriptor and
scheduling. Context's Session host imports the scheduling operations it uses.
The Context module can publish its profile independently. Session consumes
an opaque input reference through its own data contract.

* Context Memory selection

[[file:../../../../modules/ai-agentic-context/interface.ss][The Context Interface]]
owns the =memory= Feature. A downstream init selects it through the same
window as the base module.

#+begin_src scheme
(yuanxu!
  :load-modules "./modules" mode: explicit
  (ai-agentic-context +memory))
#+end_src

The Module System composes and admits the selected scope. Consumers read
its =profile= slot for Context projections. The base profile contains only
=ai-agentic-context/core=. The Memory refinement adds
=ai-agentic-context/memory=, and the Feature contract checks the final profile.
Both identities remain part of the stored projection format. Checkpoint
recovery decodes the recorded profile and revalidates the projection against
its source. Feature selection acquires no Memory store or Session host.

The first draft also underrepresented the already designed Graph Context,
ORG-only Query window, consumer-local interpretation and short-to-long
consolidation. They are restored here as inherited design, not newly invented
features. The user's clarification emphasizes the overall system meaning of
Context and the short-/long-term knowledge distinction within it.
