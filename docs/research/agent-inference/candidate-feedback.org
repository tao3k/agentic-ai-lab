* Design assessment

An Agent can often repair a missing declaration after a compiler error,
yet a recursive rule with a wrong join can run and produce plausible
rows.  A Library that only says =accepted= is therefore insufficient.
It should return typed diagnostics first, then complete relation
differences or bounded counterexamples under a named finite scenario.
The paper explicitly separates compile pass from exact output match.
Its numerical results apply to its Soufflé benchmark, model set and
prompt configurations; they do not predict Gerbil success rates.

* Discriminator

For one reachability graph, offer a correct proposal, an undeclared
helper predicate, and a compiling wrong recursive join.  Require the
Library to reject the helper, execute both admitted programs, and
show a pair present only under the incorrect rule or missing from it.
Repeat after source withdrawal; compare all rows with a separate
finite graph model, not merely a single expected answer.

* Execution transfer, 2026-10-09

Re-reading §§4.3, 5.1 and Appendix G sharpens the protocol: freeze a
candidate before grading held-out variants; demonstration feedback stays
separate. The paper's mutation families remove rules, remove body atoms
or rebind joins. They do not exercise negation, aggregate functions or
grouping scope, so their score cannot establish correctness there.

The [[file:../../features/candidate-feedback/acceptance.org][finite Scheme discriminator]] now implements complete missing/extra feedback
through the existing reasoning receipt and snapshot binding. It freezes five
hand-written proposals and compares 320 attempts over 64 finite graphs with
independent graph walks. A demonstration-pass/held-out-failure control,
withdrawal, rejected helper and unfinished attempt are included. Lean proves
the set-difference characterization; Quint checks completion and binding before
comparison publication. This closes the local discriminator described above;
model synthesis and running the released Souffle corpus remain open.
