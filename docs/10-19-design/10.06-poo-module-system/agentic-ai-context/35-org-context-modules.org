* Scope and semantic owners

This is a proposed refinement of [[file:01-system-boundary.org][Context responsibilities]],
[[file:15-unified-query-provider.org][the Org Query boundary]], and Core's
[[file:../../../../core/module-system/design/43-session-memory-recovery/12-git-project-context-model.org][Git Project model]]. Its [[file:35-org-context-modules.sysml][SysML v2 model]] makes the
roles and selected relationships explicit. Task publication for one Worktree's
selected Org modules runs through the existing POO interfaces. External
module resolution and source capture supply the effective selection.
Orgize owns parsing and Elements, Query owns its supported query semantics,
Context coordinates projections, and the Host/runtime owns effect admission.

* A leaf is relative to a traversal

A module revision exposes a namespace of declarations. A traversal may stop at
an address and return a module as its leaf; another traversal can use that same
module revision as its root and expand it further. A leaf is therefore neither
necessarily a scalar nor necessarily rendered text. Discovery of declarations
and materialization of a value are separate operations; a declaration listing
must not silently run the leaf's business computation.

| Role | Composition and identity | Exposes or binds |
|------+--------------------------+-----------------|
| Project | Logical root; may compose multiple Repo modules | Applicable shared declarations and explicit imports |
| Repo | Versioned module within a Project, not the Project identity | Project conventions, Org entry points, available interfaces |
| Worktree | Situated derived revision of selected Project/Repo cuts | Git observation, local Org, Task inputs, overrides and imports |
| Org | Addressable content module associated with a source revision | Elements, properties and links; optional declared Contract or Query interface |
| Derived Org | Worktree-owned source and separately identified module | Qualified origin anchor and origin source revision; may itself be extended |

Containment, derivation and imported interfaces are independent: an Org belongs
to a Worktree view without necessarily deriving from another Org. A derived Org
can reference an anchor in an external source without moving that source or
inheriting its permissions. Anchor identity includes source identity, source
revision and the registered anchor; a local ID or pathname alone does not
identify historical content. Missing or ambiguous anchors must remain explicit,
not silently retargeted. An Org link is not executable code or an import by
itself.

A Worktree cut retains the selected parent revision, repository and Worktree
association, and an actual bounded observation of HEAD, index, working bytes
and selected untracked inputs as applicable. A commit alone does not represent a
dirty Worktree. Capture must retain bytes or report their unavailability and
must check races at the producer boundary. None of these identities authenticates
authority or proves the source's factual claims.

* Three relationships and two kinds of order

- =derives(base revision, successor revision)= records versioned ancestry and
  declared composition/override. Persistent derivation does not mutate the base
  or sibling, though a computed value depending on final self can differ.
- =imports(importer, provider revision, interface/contract)= makes an explicit
  interface selectable under visibility rules. Import is neither a call nor a
  grant. Imported declarations may themselves create dependencies.
- =invokes(binding, implementation revision, request, source cut, authority)=
  records the actual dispatch decision and its inputs. The Host rechecks current
  authority, source and applicable Contract at the effect boundary; an old
  projection or imported interface is not standing authorization.

Declared ordered prototype parents and overrides determine effective POO
features through the actual supported C3/C4 mechanism. Do not assume C4 is
always applicable or that import, Git, evidence or Org link edges participate in
prototype linearization. Ambiguous or inconsistent precedence, unresolved
interfaces, cycles and violated hard Contracts must be reported or refused by
the applicable owner; retain the unresolved proposal for inspection. Contract
obligations cannot be overridden away merely by precedence. Final prompt order
is a separate, explicit serialization policy, not inheritance order.

* Demand, selection and evaluation

For a particular Task/consumer and selected source cut:

1. Inspect accessible declarations and choose requested interfaces, Org anchors,
   queries and explicitly needed dependencies. Record missing coverage and
   unresolved alternatives; do not treat unvisited content as absent evidence.
2. Resolve the transitive dependency closure and applicable revisions, ordered
   prototype parents, overrides, source/Contract/query cuts and visibility.
   Resolve the effective definitions or return a conflict. Changing a Contract,
   provider selection or final-self-dependent input can affect a demand even
   when the newly added module is never directly read.
3. Evaluate only what is needed within that closure using the existing Module
   mechanisms and the supported Query provider. Bind all actual reads and
   results to their source, revision, query and Contract. The provider's present
   supported Org/GQL subset is described in 15; arbitrary Org and full GQL are
   not implied by this design.
4. Serialize the admitted result for the consuming model under an explicit,
   versioned ordering and rendering policy. Record the effective inputs,
   omissions, uncertainty and result lineage. An absent Task read of a new
   independent Org need not change this projection, provided its addition also
   changes none of the selected closure, effective definitions or policy.

For example, a Worktree may import Router and Search. A Router result proposes
qualified Org anchors, symbols and evidence scope; Search is invoked against
that Worktree's bound source cut through its declared interface. A local Router
replacement can leave the Search interface unchanged. It may nevertheless
change the Search request and resulting projection. Dispatch requires separate
current authorization; a route is neither evidence authentication nor authority
to execute a tool. Other Worktrees keep their own revisions and selections.

* Reuse and invalidation

A retained evaluation is reusable only if its complete recorded dependencies,
including effective definition, final-self-sensitive inputs, source and Contract
cuts, query, visibility and current applicability, remain valid. Dependency
tracking must include reads made by computations and selection/override inputs;
an incomplete read set cannot justify minimal invalidation. Coarse invalidation
is safe when exact dependency capture is unavailable. Concurrent source or
policy changes require current admission checks and publication fencing as
specified by existing lifecycle designs.

A model KV cache is a downstream runtime optimization. Its reusable length is
at most the longest equal token prefix of the actual authorized rendered inputs,
subject also to model, tokenizer, cache format, runtime and isolation/authority
compatibility. Equal module identity, equal text, or shared Repo ancestry alone
is insufficient. Conversely, a change after an identical prefix need not erase
that prefix. Any cross-consumer sharing must satisfy the runtime's disclosure and
isolation policy independently of token equality. This design asserts no cache
hit rate or speedup and does not prescribe a provider's cache API.

* Publishing one Task projection

For a GC investigation, Task =investigate-owner= in Worktree =gc-owner-fix=
asks its Router to select Org evidence for the current hypothesis. The Router
selects a qualified =findings.org#owner-evidence= anchor and returns a proposal
for a bounded Org property query. Org Elements supply the searchable structure
and source-qualified identities. GQL defines which Elements to select and which
fields to project. In this case the Org Query Provider executes =MATCH= on
=OrgElement= with a =propertyId= equality predicate. The Search Engine
coordinates the evaluation and binds the observation to its request and source.
The finding remains owned by =gc-owner-fix=. Its selected Org Element may declare
an original =design.org= anchor at a pinned source revision. The original
participates as a selected dependency with its own read grant and GQL receipt.
An ordinary Org link remains traversable through its own authorized read.

** Org Elements are the Context search model

The Orgize ElementGraph supplies searchable objects and their structural
relations. A headline provides a scope, its property drawer supplies
structured fields, and its descendants can include paragraphs, tables, links,
and source blocks. GQL selects and projects an authorized portion of this
structure. Search coordinates the evaluation and its receipts. The Worktree
Module selection determines which source cuts can contribute Elements.

An anchor identifies an entry into the graph. For the GC investigation, a
structural query can start at =findings.org#owner-evidence=, select a child
table and an evidence link, and return the corresponding Elements with their
ancestry and source ranges. A link is evidence that the document contains a
reference. A scoped cross-file link can resolve to a separately authorized
source cut and qualified target anchor. Source-block content has no execution
semantics in Context Search.

An Org Module opts into a bounded descendant window by declaring
=descendants: (.o max-depth: 8 result-bound: 16)=. The display grant admission
digest includes the same window via =context-task-read-scope=. Both bounds
accept integers from 1 through 32. Depth counts Orgize graph edges below the
anchor. The window selects paragraphs, tables and links in that source cut.
Depth controls which Elements have rows. A row's byte range covers its full
Element, including inline contents. The result bound is checked before a
receipt is issued.

[[file:../../../../modules/ai-agentic-context/org-contract/descendants.ss][Org
descendant selection]] uses the Orgize parent relation. The
[[file:../../../../modules/ai-agentic-context/query-provider.ss][GQL Provider]]
reconstructs the window and requires its exact ElementSpace, selected
identities and projection. Each row carries the Element kind, source, byte
range, and the corresponding UTF-8 text. The receipt binds the root, parser,
source revision, window bounds and root-first ancestor paths. A path includes
the root and immediate parent, with a half-open byte range at each step. The
ordinary Query journal replays the receipt from the original source bytes.

| Case | Required observation |
|------+----------------------|
| Select two same-titled sections | Only descendants of the source-qualified root anchor enter the result. |
| Select a table and an evidence link | Return source-backed Elements with their parent lineage and ranges. Keep link resolution explicit. |
| Encounter markup inside a source block in this window | The table, paragraph and link projection uses the Orgize structural kinds. Text inside a source block remains part of that block. |
| Change a selected source revision or withdraw its read grant | Withdraw the result from current Context. Retain its historical receipt. |
| Exceed the declared result bound | Refuse the query before issuing a complete receipt. |

The descendant window scopes the existing single-node GQL selector. General
GQL path queries and automatic link traversal are outside this window.
An Org Module with the original anchor selection still issues its one-row
=propertyId= query.

** Cross-file link resolution

Link discovery runs one Orgize expression over each reached anchor's
admitted =descendants= window.

#+begin_src scheme
(org-elements link (descendant-of scope))
#+end_src

Orgize owns the Link and Attachment shapes, relation matching, and link
fields. For a relative =file:= link with a custom ID selector, Lab uses the
file field as a source key relative to the originating document's directory.
For example, =file:design.org::#design-evidence= in =A/worktree.org= looks up
=A/design.org= in the Worktree's existing =org= namespace. Its Org Module
declares =source: "A/design.org"=, =anchor: "design-record"=,
=source-generation: 2=, and its own display grant. The target anchor's unique
=CUSTOM_ID= must match =design-evidence=. The source provider supplies the
bytes after the target grant check. The lookup key is used only in the
Worktree namespace.

The module's
[[file:../../../../modules/ai-agentic-context/org-contract/templates/worktree/worktree.org][worktree.org]]
example starts with =CONTRACT_ID: context.gitops.worktree.worktrunk.v1= and
its =GITOPS_= properties. The file-local Scheme Contract uses the same Orgize
query syntax. The Scheme tests read the three raw Org files and
verify the Contract selected for each path before exercising Task receipts.

The effective Context Worktree Feature supplies the Contract family and
revision. Enabling the Context WorkTrunk Feature extends that family with
=worktrunk=. Scheme checks the resulting ID and revision against the
selected =worktree.org= root drawer during Task resolution. The native Orgize
Contract block owns the document's structure and evidence assertions.

The same expression runs at each admitted target with a descendant window.
An unauthorized or stale target blocks traversal before its own query.
An anchor repeated on the active path rejects the selection. Paths can
converge on one admitted anchor. Attachments and links outside the
registered source namespace remain reference evidence. Unreachable Modules
stay lazy, and each reached Module keeps its declared lineage and Query
scope. A Task can admit up to 32 anchors and 32 link Elements.

Each reached anchor has one Query receipt from the existing GQL Provider.
The Search batch binds =org-link-roots= and =org-links=. Each hop retains
the link Element identity and UTF-8 byte range, plus the source, generation,
anchor, source digest and Query reference at each end. Current and
historical Task receipts expose the roots and all hops. Consumers join a
hop's target to the next hop's source by its qualified anchor and Query
reference. Shared hops are recorded once.

Publication and use recheck every captured cut and grant. Replacing an
intermediate source or withdrawing its grant makes the entire batch
ineligible for current use. A late receipt retains its original chain in
history. A new target generation requires an explicit new pin. Equal
anchor text or version alone cannot substitute another target file.

** Task and receipt records

Four records bind the decision to its inputs.

| Record | Captures |
|--------+----------|
| Task demand | Task identity, target Worktree, requested interfaces and read scope |
| Resolved demand | Chosen Project/Repo parent and Worktree source cuts, effective Router and Search Contract, ordered Org modules with qualified anchors, per-source Query revisions and read grants, and any pinned origins |
| Projection receipt | Unique request, captured resolution, and ordered per-file GQL receipts with source, result and original-anchor lineage |
| Task publication | Admitted receipt and result, with current eligibility checked independently of its retained identity |

The selection dependencies include the declarations consulted to resolve a
winner or detect ambiguity. For a direct import this can be a named binding.
For a selector that enumerates matching providers it includes the consulted
candidate set and the applicable selection policy. Actual read dependencies
include source revisions, queries and the values consumed by computations.
Capture selection inputs when resolving the demand. Bind them together with the
actual reads in the projection receipt. With incomplete dependency evidence,
re-resolve and re-evaluate the affected scope conservatively.

1. Resolve the demand under its Worktree and read scope. Missing or ambiguous
   required anchors, bindings or definitions leave the demand unresolved.
   The read boundary checks authority before accessing protected inputs.
2. Issue a unique evaluation request against the resolved cuts. Validate
   actual source, query, Contract and evidence at the existing provider boundary.
3. Under the publication owner's compare-and-publish fence, match the receipt to
   the pending request and compare the captured dependency and grant revisions
   to the live resolution. A foreign or spent receipt can be retained in the
   authorized audit scope while preserving pending work and the last publication.
   A matching result from an obsolete evaluation ends that evaluation as
   historical evidence. Validate current eligibility again at final use.

| Change | Current-use decision |
|--------+----------------------|
| Declare an independently addressed Org module outside both the selection and read dependencies | Preserve the existing projection if the recorded source cut and effective definitions also stay the same |
| Edit the selected file or change the captured Worktree source cut | Require a new evaluation, even when the same Org ID or result rows reappear |
| Change the original file's generation while a derived module pins it | Withdraw current use and retain old proof. Require an explicit new original pin and then a fresh evaluation. |
| Retire the loaded Worktree Module generation or revise a selected declaration source | Withdraw current use. The next Task start re-resolves through its GitOps dependency. Once a current selection is available it can issue while a superseded receipt is still in flight. |
| Return evidence for only some selected files or substitute a different original | Treat the delivery as unbound. The complete matching receipt can still settle the request. |
| Replace the effective Router, change the selected Search Contract, or make resolution ambiguous | Withdraw affected projections. Resolve again before a fresh evaluation. |
| Return a sibling Worktree result with the same local ID, or redeliver an earlier request | Preserve the current projection and pending evaluation. Retain the delivery under audit policy. |
| Revoke and later restore the read grant | Withdraw current use on revocation. Restoration issues a fresh epoch and old evaluations stay historical. |

An edit that adds a physical Org file can change the producer's recorded
Worktree cut. The independent-declaration case applies only when the recorded
inputs stay equal. With an existing whole-source digest, even an edit outside
the returned rows changes that source dependency. Fine-grained reuse requires
a verified narrower dependency from the source owner. Historical replay stays
bound to its recorded source and remains subject to the applicable history-read
policy.

** Scheme correspondence

[[file:../../../../modules/ai-agentic-context/task-publication.ss][Task Publication]]
exposes a serialized owner for one Task within a Worktree. Worktree, Work and
WorkTrunk are GitOps Feature roles. The
[[file:../../../../modules/gitops/features/worktree/interface.ss][GitOps Worktree Feature]]
owns the Worktree prototype and the dependency on its current admitted Yuanxu
selection. The
[[file:../../../../modules/ai-agentic-context/features/worktree/interface.ss][Context Worktree Feature]]
requires =gitops/worktree= and inherits the GitOps Worktree prototype. It adds
the =tasks= and =org= declarations and publishes the existing Task operations.
The Module selection enables =(gitops +worktree)= and
=(ai-agentic-context +worktree)= for this path. The
[[file:../../../../modules/gitops/features/work/interface.ss][GitOps Work]]
and [[file:../../../../modules/gitops/features/worktrunk/interface.ss][WorkTrunk]]
Features own their revisioned binding Contracts and use the same
[[file:../../../../modules/gitops/dependency.ss][current Module dependency]]
shape. Context's =+work= and =+worktrunk= Features inherit those prototypes
and add Org roots.

The Worktree declaration supplies the inherited =project=, =worktree= and
=source-cut= and the Context task and Org namespaces.

#+begin_src scheme
(.o (:: @ (.get Context worktree-context))
    project: "gambit" worktree: "A" source-cut: "cut-1"
    tasks: (.o investigate-owner:
                 (.o org: '(findings)
                     router-revision: "router-1" search-contract-revision: "search-1"))
    org: (.o findings: '(org findings)
              design: '(org design)))
#+end_src

The caller obtains the dependency from the selected GitOps scope and uses the
inherited Context Feature through the public Task entry.

#+begin_src scheme
(def dependency
  ((.get GitOps worktree-dependency) current-module-selection '(worktrees gc-owner-fix)))
((.get Context bind-worktree!) host scope dependency)
((.get Context start-task!) host)
#+end_src

Task declarations may add a =work= dependency, a =worktrunk= dependency, or
both. Their constructors come from the selected GitOps scope as
=work-dependency= and =worktrunk-dependency=. For each used role enable that
Feature in GitOps and in Context. The corresponding Context prototype supplies
the =org= slot for the effective binding.

#+begin_src scheme
(.o (:: @ (.get Context work-context))
    project: "gambit" work: "diagnose-gc" revision: "w2"
    org: '(design findings))

(.o (:: @ (.get Context worktrunk-context))
    project: "gambit" worktrunk: "gc-review" revision: "t1"
    org: '(design))
#+end_src

Task starts with its own Org roots and appends the selected Work and WorkTrunk
roots. It resolves each name through the same Worktree Org namespace and
collapses repeated names while retaining their first position. Each selected
dependency's role, identity and revision enter the Search source cut and are
available as =gitops-dependencies= in current and historical results. GitOps
supplies a new admitted Module selection when a dependency's declared
revision changes. The Task entry re-resolves when a selected dependency is
replaced. A change in another Task's dependency leaves this Task's projection
and namespace reads intact.

The individual Org Modules export =worktree=, =source=, =anchor=,
=query-revision= and =grant=. The Task names =findings=. The Org Element with
that module's anchor can declare its original in its own property drawer.

:CONTEXT_ORIGIN_MODULE: design
:CONTEXT_ORIGIN_SOURCE: A/design.org
:CONTEXT_ORIGIN_ID: owner-evidence
:CONTEXT_ORIGIN_GENERATION: 1
:END:

[[file:../../../../modules/ai-agentic-context/worktree-selection.ss][Worktree selection]]
demands the Task's roots through the existing Yuanxu/POO namespace and follows
each selected Element's original through that Worktree's named Org Modules.
Both the source identity and local anchor must match the Element's declaration.
The original's generation must match the pin. Each dependency is separately
authorized before its source is read. An unselected Org Module does not
materialize. Explicit roots keep their declared order, and original dependencies
are appended in discovery order. Cycles, missing names and incomplete origin
properties refuse selection.

The admitted configuration records the loaded Module selection and source
digests used to resolve the declarations. Issuance, publication and final use
recheck the current GitOps dependency, Yuanxu's =admit-current= and those
digests. For a stale selection, =context-task-start!= obtains the current
loader from GitOps and repeats resolution against the effective Context
Feature. It reuses declarations whose source and anchor digest still match.
An updated original remains unavailable until the derived Org Element declares
the new pin. When a new selection can issue, the Task replaces an obsolete
pending evaluation. A matching active evaluation still occupies the active
slot. For a superseded evaluation with an issued Query ticket, the owner
retains the Query batch reference, request and Search observation admission
state, and captured GitOps revisions. The retained binding omits the source
bytes and live Module closures. Its lifetime ends on a matching delivery or
explicit cancellation. Each retained binding already consumes at least one
entry in the bounded Query catalog.

A late return is admitted by the original request and its own Query batch.
This adds one historical receipt and preserves the newer pending request and
published value. A malformed return leaves the original binding eligible for
a legitimate late delivery. Duplicate and canceled returns are unbound.

The bounded model exercises one Task in single-file and two-file configurations,
with source, effective Router, Contract and grant revisions abstracted as
stamps. Scheme admits up to 32 ordered Org anchors. Each GQL query uses the
established single-source provider and Task composes its receipts afterward.
The Scheme tests select both Feature declarations through the Yuanxu loader,
