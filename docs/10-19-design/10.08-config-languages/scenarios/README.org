These are optional research checkouts, not product build/runtime dependencies.
Their registration does not add them to a Loader or execute their configuration.
Avoid recursive initialization when only this reference is needed. A repository-wide
recursive submodule command can initialize all registered references; this is an
explicit Git operation, not evidence of runtime module loading.

Update a reference deliberately, review the gitlink change and revise the affected
source analysis. Do not follow a moving branch implicitly or format upstream files.
The migration retained the four previously studied commits and verified every
previously copied file against its corresponding checkout before removing the
redundant snapshot manifests. No configuration evaluation or deployment was run.

* Dependency and execution boundaries

A complete upstream Git checkout is not a resolved package dependency closure.
Relative paths and upstream manifests remain unchanged. Konfig cases retain their
kcl.mod/lock files; OCI dependencies are not fetched. The AWS example references a
generated tf-ncl-schema.ncl absent from the pinned tree; no replacement is supplied.
Sandbox runtime binaries/local paths and HiveBus flake inputs are not resolved.
Upstream golden files are upstream expectations, not results produced here.

Compare actual APIs/inputs, derived resource identities, validation and demand.
Do not infer a typed cross-service connection protocol merely from DNS use, or
that schema.instances() means the whole global package catalog is loaded.

field contracts and resource consumers. [[file:../09-application-scenario-admission.org][Application admission]] remains unexecuted
