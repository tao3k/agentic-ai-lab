* Boundary

The C binding and process bootstrap belong to Agentic AI Lab, never Yuanxu.
=call-with-flake-session= parses a reference, strictly checks its lock and
selects an output function using =libflake-c=. =session-query= calls that
function in the same EvalState. Scope/lifetime are explicit; no evaluation
session is created by a Scheme declaration.

The opt-in product adapter =call-with-flake-evaluator= instead owns a lazy POO
handle used by =NixFlakeSource. evaluator:=. Each independent query strictly
relocks and reselects in one Store/EvalState; it does not authenticate a later
source generation with a cached output thunk. It closes at the functional
scope boundary and refuses escaped use. Details, fallback limits and actual
product controls are in [[file:../../docs/10-19-design/10.08-config-languages/20-nix-flake-source-c-api.org][20 Product Flake Source C API]].

Compatibility requires numeric =(major, minor) >= (2, 34)= and actual header,
linker and runtime probes. =dependencies.nix= selects the CLI and C libraries
from the caller's Nix package set. The qualification reads the resulting
toolchain through its executable and pkg-config paths. Nix owns artifact reuse.

* Direct embedding and startup ownership

The default test uses the installed Gerbil executable and preloads
=libnixflakec.dylib= before Gambit initialization. This is direct in-process
FFI: no evaluator worker or Nix CLI is launched for an API query.

This ordering matters on macOS. Loading libstore with =dlopen= after Gambit
initialization runs =Settings::getDefaultExtraPlatforms()=, which invokes
=arch -arch x86_64 /usr/bin/true=. The recorded abort backtrace goes through
=Pid::wait=, =runProgram= and the library's global initializer. Gambit's
SIGCHLD reaper can consume that child first. Early runtime-library loading
avoids that particular initialization race without replacing signal handlers.
The launcher targets the actual installed =current/bin/gxtest=, because a
system-interpreter wrapper may discard =DYLD_INSERT_LIBRARIES=.

Preloading itself runs Nix's runtime initializers, including its platform
probe; it is an explicit process-startup action, not inert module discovery.
The successful qualification does not prove that every Nix feature that
spawns subprocesses can coexist with Gambit's child reaper. Realization,
remote builders and arbitrary execution remain separate qualifications.

* Read-only expression currentness

Expression currentness can reuse a Store connection across an execution while
creating a fresh EvalState for each query. Reusing an EvalState can retain an
import after its file changes. Each pre-effect and post-effect guard still
evaluates the expression and compares its derivation with the admitted path.

The pinned Nix version selects the derivation write path using the process-wide
Store setting. The public EvalState builder alone does not establish CLI
read-only behavior. Qualify any replacement with a new derivation that remains
unregistered, an atomically replaced indirect import that is rejected, and an
unchanged real Provider whose original derivation is returned. A process that
owns this global setting must also own startup, cancellation and shutdown.
Include those costs in the execution comparison.
See [[https://github.com/NixOS/nix/blob/2.34.4/src/libexpr/primops.cc#L1690-L1695][the derivation write boundary in Nix 2.34.4]].

For an in-process expression adapter, pass names and string values directly
through the C ABI. Qualification must exercise a long-running pure Nix
expression under a short deadline, require cancellation before it returns a
value, and verify that a following query still works. Both the Scheme watchdog
and the Nix thread-local interruption predicate allowed the tight fold probe
to finish. The subprocess boundary still owns the production timeout and
cleanup guarantees.

The expression worker package keeps one read-only Nix Store connection and
creates a fresh EvalState for each query. Its pipe uses Nix's length-prefixed
serialization for argument names and values. The worker uses Nix's own
configuration parser before and after evaluation to reject changed settings,
including Store routing and nested config includes. The package also exposes
the matching =nix-instantiate= for the ordinary CLI path.

For an OpenTofu expression Source, set the existing Nix Config =instantiate=
to =bin/nix-instantiate= in this Nix output. The admitted baseline carries
that selection into OpenTofu's explicit =.run=. Ops supervises one evaluator
after the execution task graph passes preflight. The existing per-query
watchdog remains active. The final currentness check runs after the
evaluator exits. Commands
without the paired executable and Flake Sources use their existing paths.
Source observation, environment changes and working-directory changes keep
individual queries on the configured CLI.

** Native Nix configuration replay control

The Nix 2.34.7 C API moves the builder's evaluator and fetch settings into
each new state. Its standard loader parses the configuration independently
for both settings objects. The isolated worker instead applies the native
parser's ordered setting updates and override-reset position to each
fresh builder. It still reads the configuration before and after each
query, retains one Store connection, and constructs a fresh EvalState.
See the [[https://github.com/NixOS/nix/blob/2.34.7/src/libexpr-c/nix_api_expr.cc#L139-L176][pinned C API implementation]].

Both workers matched the CLI derivation for an expression with a relative

derivations unregistered. Editing an included Nix configuration file
caused both workers to refuse the next query. A fresh session with the
included =restrict-eval= setting then refused the same path, as did the
matching CLI, confirming the replay reaches the effective evaluator.

* Locking and source boundaries

The bridge always selects =nix_flake_lock_flags_set_mode_check=. It never
writes or virtually updates a lock. Input overrides must be locked references;
adding one preserves check mode. Lock creation in the test is explicit fixture
preparation performed by the CLI, outside measured evaluation.

The existing source-currentness consumer runs before and after a query and
before returning a cached POO preview. The bounded fixture explicitly records
its complete known file closure. This is not automatic general-purpose Flake
source discovery. Neither a warm EvalState nor a locked input authorizes
returning a stale configuration. The parent plan and derived child plan have
separate POO receiver caches; adding Null never changes the cached AWS parent.
