#+title: Independent Session implementation boundary
#+date: [2026-10-30]

* One owner for each contract
:PROPERTIES:
:ID: context-independent-session-implementation
:END:

This implements G1 of [[file:31-design-audit-and-next-delivery.org][the source audit]]. It preserves the boundary in
[[file:01-system-boundary.sysml][the existing SysML architecture]]: Context composes an independent Session.
Session preserves opaque producer bindings; it does not interpret Org evidence
or acquire a Memory store in order to create, select or recover a Session.

| Responsibility | Implementation owner | Downstream use |
|----------------+----------------------+----------------|
| Durable policy, resume identity, validation and receipt projection | [[file:../../../../modules/session/durable-policy.ss][Session durable policy]] | Memory store/recovery and Sandbox policy consume the same inert contract |
| Session identity, Attempt proposals, recovery obligations | [[file:../../../../modules/session/interface.ss][Public Session interface]] | Context composes these values and owns evidence/current-use admission |
| Org selection plus Memory store and Session intent policy | [[file:../../../../modules/ai-agentic-context/features/memory/session-selection.ss][Context Memory selection adapter]] | Published by the existing [[file:../../../../modules/ai-agentic-context/features/memory/interface.ss][Memory interface]] |

The policy implementation moves once from Memory to Session. Its POO values,
receipt schemas, predicates and durable diagnostics remain unchanged. Memory,
Sandbox, examples and tests import that owner directly. The deleted paths have
no forwarding modules or duplicate declarations.

The Org adapter moves once in the opposite direction. Its existing Session
intent names/schema remain stable because they describe the receiving intent;
they no longer imply that Session imports a query engine or Memory backend.
Policy eligibility still does not authenticate source evidence or publish a
Memory head. All original refusal predicates remain in this adapter.

* Publication and execution

The existing interfaces close the public surfaces. Session syntax exports its
own durable policy; Memory's interface exports its own Session selection adapter.
The existing =init.exports.std-make-spec= and native import closure discover
these owners. This change adds no build inventory, runner, environment variable,
package manager, or alternate export protocol.

[[file:../../../../t/session-independent-test.ss][The isolated Session consumer]] imports the entire public interface. It inspects Gerbil's
actual loaded modules, with a positive Session matcher and a negative Context
matcher, then exercises public selection, durable policy and real Attempt
proposal/recovery functions. A descriptor-only check would miss the old reverse
implementation imports. This gate qualifies independent Session proposals, not
final Context result publication or external effects. The separate
[[file:../../../../t/session-attempt-test.ss][Attempt Suite]] imports the same facade and remains reusable inside Context
without asserting that a combined Context process has no Context modules.

[[file:../../../../t/memory-org-selection-test.ss][The Memory composition consumer]] imports Memory's public interface. It preserves
source-cut, source-byte, query grant, store scope, inactive Session and stale-head
refusals. Context's original native suites separately own proof/support/journal,
active Attempt terminal CAS, invalidation, cancellation/recovery and cross-Session
consumers. No intent-only test substitutes for those native integration gates.
