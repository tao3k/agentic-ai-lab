The proof arm changed only the negation/count observation. That task
already scored 3/3 on both choice and bounded claim in the typed arm,
and all three proof responses matched it. The other four tasks were
unchanged controls with identical typed and proof observations. This
pilot therefore shows *no observed improvement* from adding the
founded receipt on this fixed corpus; it cannot rule out a benefit on a
different task or prompt.

All six closed-cut answers still said =release_authorized= even though
the native temporal receipt denied release. The guard recorded
=withheld / native-denies-release= for those six outputs, three in each
arm. It recorded =observation-only= for the other 24. Guard containment
does not make the six model claims correct and is not effect authority.

* Cost, timing and limits

The typed arm used 3,228 input and 195 output tokens; the proof arm
used 3,396 input and 195 output tokens. Total reported use was 7,014
tokens. Median model-call times were 0.575 s typed and 0.505 s proof;
one typed call took 5.458 s. These small, sequential samples do not
establish a latency advantage. Native preparation was shared across
requests and excluded from those model times. The live JSONL recorded
the earlier source-fixture times, but not the separate founded-receipt
construction time, so it cannot support a complete end-to-end timing
comparison.

Five finite questions and three calls per arm do not establish general
model benefit, complete Rust Ascent parity, caller intent, source
authenticity, temporal causation, release authority or deployed
behavior. The closed-cut failure remains a concrete reason to keep the
deterministic output guard at the consumption boundary.
