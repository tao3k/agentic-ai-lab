* Actual ownership and calls

| Entry | Current behavior | Rebuild classification |
|-------+------------------+------------------------|
| =OpenTofu Build.prepare= | Copies the configured Source for one request, projects final Provider demand and currentness observations. | Scheme object construction, not itself an EvalState allocation. |
| Its =.realize= | Refines arguments or the =selection= data input and calls Source =.prepare=. | A changed data-input snapshot is a changed Nix context even if its directory spelling is unchanged. |
| =NixSource. .prepare= | Derivation/artifact are lazy receiver-local slots. | Repeated warm slot reads already avoid repeating construction/realization. |
| Publication =admit-current= | Calls =admit-derivation!= through the derivation-query mode. | Independent query must not be replaced by a cached admission or old output. |
| =NixFlakeSource. .instantiate= | Contract check, source check, CLI query, source check. | Each CLI process has its own evaluator; no native session is held here. |
| Serialized =.guard-form= | Reconstructs a Source in the generated guard's process. | Independent process/context; no native state-restoration protocol exists. |
| Binding =call-with-flake-session= | Creates one state, locks/selects once, runs the callback and closes it. | Already one state across AWS and Null inside that callback. |
| Qualification fresh-state rounds | Explicit independent sessions for cold controls. | Intentional measurement, not an accidental product reconstruction to remove. |

The only =nix_state_create= in the binding is inside =pf_nix_create=. Its
functional session brackets call it once per independent callback lifetime;
there is no additional creation inside =session-query=. Baseline assertions
continue to require one Store, one state and one strict lock across both final
candidate values. No safe redundant native construction was found there.

The product CLI's package route uses =path-info --derivation= with its existing
exact-attribute handling; its applied-function route uses =eval --raw --apply=.
The latter passes an ordinary Nix attrset to the function and reads =drvPath=.
The qualification instead passes a JSON string to a function returning a
receipt string. It explicitly uses =--impure= for matched CLI controls; the
product command does not. Argument/result projection and evaluation-mode
parity remain integration work, not interchangeable transport details.

* Executable stale-import counterexample

The existing three-round Case now models exactly the default local header
observation subset: =flake.nix= and =flake.lock=. This subset is intentionally
insufficient and never grants acceptance. It is an analysis control derived
from the inspected product collector, not a claim that the full product
Scenario was executed or that its richer custom observations were discarded.

After the parent/child computations and their real generated-Contract admits,
the final round modifies the imported =stamp.nix= from =1= to =2=:

#+begin_src scheme
;; Existing full observations still reject BEFORE entering the cached state.
(write-input stamp "2")
(let (count (session-calls session))
  (assert 'staged-source-change-refused
    (rejected? (cut staged both "stale")))
  (assert 'stale-before-native-call (= count (session-calls session))))

;; Negative control only: header checks pass, but reuse can return stale imports.
(let* ((cached
        (checked-query headers
          (lambda ()
            (session-apply! session both)
            (session-result session "receipt"))))
       (fresh (cli-query both "true" "lib.providerArtifacts" headers)))
  (assert 'headers-only-reuse-retains-stale-import (= (field cached 'stamp) 1))
  (assert 'fresh-evaluation-observes-import-change (= (field fresh 'stamp) 2))
  (assert 'same-lock-does-not-prove-current-imports (not (equal? cached fresh))))
#+end_src

All three negative-control assertions passed. A lock file fixes inputs; it is
not a complete identity for a mutable local Flake tree or arbitrary impure
imports. Comparing only reference/attribute/lock bytes and retaining a state
would weaken the existing full-source rejection. This control retains all
original two-candidate admission, parent-cache and unused-awscc laziness checks.

* Decision and remaining integration work

Keep the existing efficient binding lifetime and the product's independent
currentness checks. Do not add a global pool, identity table, cached admission
or Source pointer slot that can hide changed imported values. The evidence
does not justify removing those queries under a "same lock" shortcut.

Product convergence is still incomplete. It requires the current module
migration/build dependencies to become executable, then a real Source-to-C-API
connection preserving argument/result semantics, native evaluation mode,
locked data-input identity and transitive source currentness. That connection
must prove that warm reads cannot hide an imported-file change before it
replaces the existing CLI checks. Reuse belongs inside an explicit validated
operation lifetime; the already demonstrated cost reduction alone does not
supply those conditions. No Gerbil/compiler sources or production runtime
were changed by this audit.
