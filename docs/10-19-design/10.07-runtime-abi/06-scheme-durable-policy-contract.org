#+title: Scheme Durable Policy Contract

* Decision

Durable policy belongs to the Scheme control plane.  Python, Rust, Marlin, and
other runtime languages should implement durable substrates and adapters, not
the durable strategy engine.

This keeps Agentic AI Lab's durable behavior in one semantic owner while allowing each
runtime to use the best local execution libraries.

* Host an existing Scheme VM

Use one Durable engine under the existing product module selection.
The engine owns next-occurrence selection, handoff identity, admission,
replay and recovery. Scheme and POO define the configuration and
decision semantics. A runtime host supplies time, durable storage,
provider calls, cancellation and resource management. Host storage
implements the engine's conditional commit; the host does not infer
whether a missing external receipt means success or failure.

The native entrypoint is the [[file:../../../bindings/runtime-c/include/agentic_ai_lab/semantic.h][Semantic C ABI]].
=semantic= names the application operations exposed across this boundary.
The VM itself is Gambit/Gerbil. The C host owns VM open, foreign entry,
result ownership and close. The trusted Context command lane already
routes to an attached Scheme runtime service. Agenda admission is a
proposed extension of that service. POO objects stay in the VM; the
host exchanges bounded inert data and releases ABI-owned result buffers.

The native entry thread and the Scheme Actor owner have different jobs:

| Layer | Responsibility |
|-------+----------------|
| Rust or Go host | Run OS-facing work, including blocking provider I/O; queue calls to the VM entry thread. |
| C host / VM entry thread | Keep open, call and close on the same OS thread. The current native profile is process-global and uses parallelism level 1. |
| Gerbil Actors / Gambit green threads | Run the Context owner, timer and Session endpoints inside the VM. The Context owner serializes its state transitions and journal commit. The timer posts an observation; Session keeps its own Attempt lifecycle. |

The existing [[file:../10.06-poo-module-system/agentic-ai-context/28-hybrid-runtime.org][hybrid runtime design]] describes the bounded owner ingress.
The foreign entry thread is a boundary for native callers. Scheme green
threads are scheduled inside the VM and can make progress cooperatively
under the single-processor profile. Rust can own the entry thread
directly; Go can pin the goroutine that owns it to one OS thread.
Host tasks return provider results to the existing owner path. The
current native host profile establishes local concurrency; independent
VM instances and parallel Scheme execution require separate qualification.

** First end-to-end slice: Durable Agenda

Use the [[file:../10.06-poo-module-system/agentic-ai-context/org-durable-declarations.org::#durable-agenda][Org Element Query and registered Action]] as the host integration
case. The existing Query boundary supplies a typed occurrence and its
source reference. Scheme decides the next wake through the existing
clock owner. At a wake or restart the Context Actor rechecks the relevant source, authorization and occurrence
state before admitting a handoff. The substrate persists the admitted
decision before releasing its effect. It returns provider evidence
through the trusted host lane, and Scheme interprets it against the
frozen decision. Unknown outcomes stay in reconciliation.

The native Agenda slice uses the existing trusted Context command
lane with the =agentic-ai-lab.agenda-request.v1= schema. =open= binds
an Org source, journal, fixed timezone offset, registered action name
and the host's current authorized Element IDs. =refresh= replaces the
permission snapshot and recalculates the next wake. =take= returns a
handoff only after the owner rechecks the current selection and commits
its stable key. A subsequent process supplies current permissions again.
The bounded projection selects single timed =SCHEDULED= occurrences on
open headings with stable IDs. Each ID is a one-shot notice in its source.

The Rust qualification driver consumes the handoff with a local file
sink. It exercises revocation before wake and process restart without
an external receipt. Go can consume the same trusted command schema
through the existing C ABI.

* Scheme Responsibility

The Scheme layer owns durable policy families and functional strategy
combinators for:

- checkpoint timing
- checkpoint id ownership
- interrupt and resume legality
- plan digest compatibility
- state projection
- retention and compaction
- replay and idempotency
- write consistency and conflict strategy

The Scheme layer should project those policies into a durable manifest that can
cross the runtime ABI.

* Python Responsibility

The Python runtime package owns adapter execution:

- AnyIO async execution
- CFFI or ctypes ABI integration
- Turso durable storage
- checkpoint CRUD
- store CRUD
- runtime conformance tests

Python should consume durable policy manifests and apply their runtime-facing
requirements.  It should not become the durable policy source of truth.

* Minimal Manifest V1

The first stable manifest only needs fields that Python can enforce without
inventing policy:

- =policy-id=: stable manifest id
- =owner=: expected to be =scheme=
- =checkpoint-id-strategy=: =runtime-generated= or =provided=
- =require-plan-digest-match=: whether resume must reject changed plans
- =history-retention-limit=: optional number of checkpoints to retain
- =receipt=: optional Scheme durable policy receipt

Future versions can add state projection, replay, compaction, and conflict
policies once the Scheme durable mechanism is stronger.

* Adapter Rule

Runtime adapters must treat the manifest as policy input, not as an advisory
comment.  If a manifest asks for a behavior the adapter cannot enforce, the
adapter should fail early with a typed runtime durable policy error.

* Current Python Landing

Python accepts =RuntimeDurablePolicyManifest= and wires it into the Turso store
and checkpointer.  The current adapter enforces:

- checkpoint id strategy
- optional checkpoint history retention

Plan digest validation remains in =RuntimeGraphProgram= resume handling because
that layer has the validated runtime graph plan receipt.

Python also exposes =RuntimeDurableAdapter=.  The adapter consumes the Scheme
policy manifest, creates the runtime substrate, and emits a
=agentic-ai-lab-durable-adapter.v1= receipt.  This is the handoff shape other runtime
languages should mirror: policy in, substrate adapter out, receipt back.
* 2026-07-06 Scheme Runtime Manifest Closure

Scheme durable policy is not complete if downstream runtimes only receive a thin Python-side placeholder.  The stable owner is the Scheme policy family, and runtime languages should consume a bounded manifest projected from a POO policy receipt.

* 2026-07-06 Durable Runtime Envelope Closure

The policy manifest is necessary but not sufficient for runtime language adoption.  A runtime also needs the durable store contract, backend selection surface, and operation vocabulary in one bounded carrier.  Scheme now owns that full envelope.

Implemented closure:

- Scheme module: =:agentic-ai-lab/modules/memory-core/durable/runtime-manifest=.
- Canonical schema: =agentic-ai-lab.durable.runtime-envelope.v1=.
- Public carrier helpers:
  - =agentic-ai-lab-durable-runtime-manifest-alist=
  - =agentic-ai-lab-durable-runtime-manifest-string=
  - =agentic-ai-lab-durable-runtime-manifest-bytes=
- Envelope content is projected from POO receipts:
  - durable policy manifest
  - durable runtime store contract receipt
  - durable runtime store backend receipt
  - backend operation vocabulary and command argv hints

Runtime language contract:

- Runtime languages consume the envelope as bytes.
- Runtime languages must not parse Scheme source or manufacture Scheme handlers.
- Runtime languages can validate envelope shape before executing storage/checkpoint/recovery operations.
- Python exposes =RuntimeDurableEnvelopeManifest= and =coerce_runtime_durable_envelope_manifest= for this role.
- Python =RuntimeDurableAdapter.turso_from_envelope= can construct a runtime durable adapter directly from the Scheme envelope bytes.

Primary validation gate:

- Python: =uv run --project packages/python-runtime pytest packages/python-runtime/tests --quiet --durations=8=.
- Scheme: =gxpkg build -g= plus focused =gxi= durable tests with =GERBIL_LOADPATH=.gerbil/lib=.
- =py-harness check= remains a semantic audit tool, not the primary test command.

Implemented closure:

- Scheme module: =:agentic-ai-lab/modules/memory-core/durable/policy-manifest=.
- Canonical schema: =agentic-ai-lab.durable.runtime-policy-manifest.v1=.
- Public carrier helpers:
  - =agentic-ai-lab-durable-policy-runtime-manifest-alist=
  - =agentic-ai-lab-durable-policy-runtime-manifest-string=
  - =agentic-ai-lab-durable-policy-runtime-manifest-bytes=
- Runtime-facing fields are projected from =agentic-ai-lab-durable-policy->receipt=: policy id, checkpoint id strategy, checkpoint store, repair mode, action classes, runtime owner, receipt schema/kind, receipt validity, and receipt diagnostic count.

Runtime role boundary:

- Scheme owns durable policy vocabulary and validation.
- Python, Rust, Marlin, or another runtime consumes manifest bytes over FFI/C ABI and executes storage/checkpoint operations.
- Runtime adapters may validate the manifest carrier, but should not invent a competing durable policy system.

Validation notes:

- Development tests that consume package-local modules must use =GERBIL_LOADPATH=.gerbil/lib= unless the package has been formally installed into the active Gerbil home.
- =gxpkg build -g= compiled the new runtime and test targets once, then returned to hot cache behavior at roughly sub-second package checks.
