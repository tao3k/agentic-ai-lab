The tool arm corrected the three negation/count choices in this tiny
corpus, but the boundary score fell. All six wrong-join responses
selected =verified_intent= even though the tool only checked candidate
rows. All three tool-arm closed-cut responses selected
=release_authorized= while the module receipt had
=release-authorized? #f=; all three baseline responses selected the
no-authority label. This is a concrete interface and comprehension gap,
not evidence that the temporal module itself authorized release.

Median model call time was 0.672 s baseline and 0.605 s tool; this
excludes tool setup. The dry-run tool observations took 34.809 s for
the shared path worker, 33.099 s for finite evidence and 13.546 s for
the temporal fixture on this macOS checkout. These cold costs were
amortized across tasks; no end-to-end latency improvement is claimed.
Reported input tokens totalled 1,845 baseline and 2,862 tool; output
tokens totalled 193 and 189 respectively.

* Repair hypothesis and next test

The Python Testing adapter transported Scheme =#f= as a JSON string
and sent complete candidate rows without an explicit intent boundary.
The next adapter should preserve boolean =false= as a JSON boolean and
carry typed =intent_verified=false= and =release_authorized=false=
fields. Keep the native module semantics unchanged. Freeze that new
observation shape as the typed protocol before another model request, and compare the
old and new tool observations on the same five tasks with the same
model and request budget. This is an interface hypothesis; the baseline
scores do not establish that the repair will help.
