#+title: User Configuration and Module Publication Contract
#+language: en

* One selection authority

The repository root [[file:../init.ss][init.ss]] declares module windows through
=yuanxu!=. There is no nested =user-interface/init.ss=, Profile registry, custom
=load!=, or product =use-module= dispatcher. =rename: Profiles= names a module
window; it does not change selection, admission, inheritance or loading rules.
Native lexical =use-module= for an already acquired semantic value is distinct
from loading a file or selecting another module graph.

The root selects user-owned sources with ordinary source rows:

#+begin_src scheme
;; In the existing modules window:
(my-module @ "./user-interface/custom/my-module")
;; In the existing scenarios window:
(developer @ "./user-interface/scenarios/developer")
;; In the existing Profiles window:
(langgraph @ "./user-interface/profiles/langgraph")
#+end_src

These are clauses of the one root declaration, not additional declarations or
manual linking steps. Module identities are unique across windows.

* Fixed source responsibilities

- =types.ss= owns Types and Contracts.
- =config.ss= owns ordinary default configuration values.
- =objects.ss= owns POO prototypes and domain projections over final Config.
- =func.ss=, when present, owns named functional algorithms.
- =interface.ss= declares the module's identity, requirements and publication.

The existing Yuanxu role wrappers own compiler surroundings and admitted
lexical bindings. User modules do not add =gerbil.pkg=, loader factories,
import-prefix registries, runtime workers or test schedulers. Normal package
imports still express library dependencies inside role implementations.

Profiles now use =profiles/<name>/{types,config,objects,interface}.ss=. Their
Config is ordinary data. The reusable =Profile.= prototype reads its bound
final Config and constructs the existing SemanticModuleContract value. It does
not capture a parent's already projected profile. The module scope publishes
=profile= and =defaults= through its declared Record Contract.

* Read published values

#+begin_src scheme
(import (only-in :agentic-ai-lab/init agentic-ai-lab.init.exports)
        (only-in :clan/poo/object .get))
(def graph-profile
  (.get agentic-ai-lab.init.exports Profiles langgraph profile))
#+end_src

The executable consumers use this exact path. The Module leaf is the configured,
admitted POO object itself; there is no =scope= facade to unwrap. Tests remain
on the independent =init.exports.tests= projection. Reading a namespace or test
metadata must not execute a runtime operation.

* Domain behavior is retained

SandboxProfile, SemanticModule, Scenario Case, pipeline and runtime-intent
Contracts remain domain boundaries. Domain constructors and inert diagnostic
projections are not another module-selection protocol. In particular, the
Developer Scenario's backend intent rows describe its preview inputs; they
are not the root's selected module graph and cannot activate those backends.

Sandbox configuration uses native POO construction and inheritance; existing
backend conversion and Contract functions still validate final values.
Funflow, Session and Loop Engine configuration calls their own APIs directly.
No central macro recognizes their names and reexports all their libraries.

Source observations, requirements, final scope admission and publication stay
owned by Yuanxu. A changed source epoch requires a fresh selection; an admitted
snapshot is not silently repurposed. Independent admission boundaries still
recheck currentness. Native Gerbil loading and POO slot caching own reuse;
there is no Profile-specific cache or compatibility loader.

* Tests and effects

Use the existing Just entrypoints around the official Gerbil/std/test tool.
Tests do not load another runner or start a process merely to invoke std/test.
Execution remains explicit behind Ops or the runtime handoff boundary. Module
selection, Contract admission and plan preview do not grant effect authority.
