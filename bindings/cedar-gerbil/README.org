#+title: Cedar Gerbil binding workspace

This directory is the package-management owner for the Cedar/Gerbil boundary.
Its root =Cargo.toml= owns the lockfile, resolver, profiles, and member set.

The workspace contains two explicit crates:

- =crates/cedar-authority=: Cedar projection, dual witnesses, Runtime Host
  protocol, signed decisions, and single-use grants;
- =crates/cedar-gerbil=: the thin Gerbil POO/native projection adapter and its
  native conformance fixture.

The =cedar-gerbil= crate directly depends on the pinned =cedar-poo-bridge=
from =cedar-poo-spec=. Its private [[file:crates/cedar-gerbil/src/artifact.rs][artifact adapter]] checks that a Gerbil POO
authority snapshot has exactly the policy IDs, Cedar sources, schema, and
entities in a validated Lean/Cedar case. The public
=NativeAuthority::new_with_validated_case= entrypoint requires the Gerbil POO
snapshot; the bridge cannot assemble policy inputs or publish an authority.
The Gerbil POO owner supplies composition provenance through its normal
projection.

Run the default workspace gate from the repository root with:

#+begin_src sh
cargo test --locked \
  --manifest-path bindings/cedar-gerbil/Cargo.toml
#+end_src

Feature-specific qualification remains explicit; see each crate's README.
There are no sibling standalone Cargo packages under =bindings/=. A member
must not add its own =Cargo.lock= or profile tables.

The workspace metadata names four explicit outer-build inputs. Cargo produces
=AGENTIC_AI_LAB_CEDAR_RUNTIME_CORE_ARCHIVE=; Lake links that archive and the Cedar
Lean object graph once into =AGENTIC_AI_LAB_CEDAR_RUNTIME_HOST=. The runtime owner
provides =AGENTIC_AI_LAB_CEDAR_RUNTIME_SOCKET=. The separate
=AGENTIC_AI_LAB_CEDAR_NATIVE_PROBE= remains a diagnostic qualification artifact.
Nix, Bazel, or another outer build owns every store/runfile path. No member
derives a repository root, =target= directory, or Lake cache path.

The repository exposes one outer-build entrypoint with a required output:

#+begin_src sh
just build-cedar-runtime-host "$out/bin/cedarRuntimeHost"
#+end_src

The command builds the Cargo archive, gives it to Lake as an explicit input,
then copies the single linked Host to the requested output. Cargo and Lake
build directories are private builder state; neither is embedded as a runtime
path. =CARGO_TARGET_DIR= and =AGENTIC_AI_LAB_CEDAR_BUILD_PROFILE= (=dev= or
=release=) remain ordinary builder controls. The generated devenv profile
supplies Cargo, Rust, elan, and just without entering a shell;
=lean-toolchain= selects the exact Lean release.

Qualify the exported artifact itself with:

#+begin_src sh
just test-cedar-runtime-host "$out/bin/cedarRuntimeHost"
#+end_src

For an atomic downstream scenario, supply a JSON case manifest, the built Host,
and an exported =.cedar= file:

#+begin_src sh
just test-cedar-case CASE.json "$out/bin/cedarRuntimeHost" POLICY.cedar
#+end_src

This command is a diagnostic shortcut for case replay. It does not replace the
normal application path: downstream Lean code compiles to a =.cedar= artifact;
Scheme loads that artifact with =agentic-ai-lab-cedar-policy-file=, composes an
admitted POO authority snapshot, and passes its projection through the native
Gerbil binding to the Runtime Host. =lean-poo= itself is a Lake package without
a Rust crate. =cedar-poo-spec='s Rust bridge is a pinned dependency of this
binding for validated artifact comparison; it does not replace the
POO-owned authority snapshot or perform Host admission.

The diagnostic manifest contains one authority bootstrap with an empty =policies= array
and a nonempty =cases= array. Each case contains =name=, =proposal=, and
=expected_status= (=authorized= or =denied=). The command parses the Cedar file
with Cedar's official policy-set parser, admits its static policies into the
existing authority boundary, and compares every case with both independent
Runtime Host engines. An expected =denied= result must be an error-free Cedar
decision: a policy evaluation error fails the case even when Rust and Lean
agree on =deny=. No industry-specific Rust test is required. The command
does not confer governance admission: the manifest supplies that claim, which
must be verified by the application host before production publication.
Use =just inspect-cedar-file POLICY.cedar= to parse and count a multi-policy
artifact without starting the Host.
The CI job replays [[file:fixtures/atomic-case/manifest.json][a domain-neutral case manifest]] against
[[file:fixtures/atomic-case/policies.cedar][a two-policy Cedar artifact]] through this same CLI.
Its Host qualification also uses [[file:fixtures/atomic-case/overflow.cedar][a schema-valid overflow policy]] to check
that aligned Rust and Lean evaluation errors fail case replay.
One Scheme POO policy value may carry a Cedar file containing multiple static
policies. The native Cedar parser expands the set under deterministic bundle
identities; templates still require explicit linking.
One Host and one Authority serve all cases in a manifest. The diagnostic
command consumes each issued grant inside that Authority to validate its
request binding and clear pending state; it never passes the returned handoff
to an effect dispatcher. Its final line reports case count, policy count,
locally consumed grant count, worker time, and elapsed time.

The strict Runtime Host starts an isolated Rust worker and then an isolated
Lean worker for every request. This enforces per-engine deadlines and crash
containment but is expensive for a large case matrix. Downstream projects
should use their Cedar export/conformance command for broad policy matrices
and reserve this Host command for selected end-to-end admission cases.
Atomic commands limit rebuild scope; they do not remove worker startup cost.
