# Branch-entry Library comparison — frozen before model execution

The existing public `ComputationalEvidence.observe` binding reads native path
conclusions at every branch entry. Fact receives the conclusions; Scheme receives
the same conclusions plus named support nodes. Baseline receives neither. The
complete task graph, common feasible nonoptimal starting selections and six
branch constraints stay identical across arms. No anti-repetition instruction,
synthetic tool call, native optimization answer, or oracle feedback is supplied.
The native evidence store retains one source-bound proof across sibling branches;
Python projects evidence and performs the existing consumer experiment only.
This is finite computational provenance, not consumer authority or temporal trust.

The two task fixtures, question, exhaustive independent BFS/subset grader and
32,768 input-plus-all-output token ceilings are unchanged from the prior run.
The model/low reasoning setting stay fixed. Output transport and the primary
annotation rule change prospectively; they are not retroactively applied to old
results. Every complete or failed paid response, cached/replayed input, thinking,
arguments and final text is charged. No unused allocation is called savings.

Each first call has a 2,048-token thinking/output checkpoint and the same available
`submit_selection` tool with automatic tool choice. On known max-output truncation containing only reasoning
items, one 256-token non-thinking submission continuation projects the exact thinking text into an ordinary assistant message
without added user/system instructions. Partial tool calls/messages are rejected,
not salvaged. The first call reserves sufficient budget for this continuation.
Completed submission after a truncated checkpoint does not mean thinking completed.
A separate retained-trace live transport check must pass before the solver runs.
Its cost is reported separately, never hidden in the experiment's gains.

All native entry-packet and replay input is charged. Later sibling input may be
bounded from the previous measured first-input count only when every other
request/context field matches, with conservative old/new branch byte allowances.
Actual provider usage must be below every reservation and the trajectory ceiling.
No timeout or total budget is widened to turn a failure into a pass.

Primary direct annotation partitions every visible character. Frozen literal
syntax counts maximal arrow chains of at least three nodes, adjacent ordered
edge-pair lists and endpoint-preserving via node lists, with independent directed
truth checks and exact raw offsets. Overlapping encodings are one occurrence.
Repeat counts are separated into same-response, same-branch and cross-branch;
only actual chain episodes count. Supplied-chain reconstruction is separate from
new literal conclusions. Other semantic lines remain explicitly unresolved.
This measures visible explicit reconstruction, not hidden inference or exhaustive
natural-language semantics. All 38 previously reviewed positive spans are captured
in a 263,647-character replay calibration; that small reference set is not a
statistical recall estimate. Failure/empty-thinking coverage is not a zero-repeat
observation. No annotation model is called and no labels depend on solver score.

Report branch coverage, objective quality relative to the common start at matched
spend checkpoints, native builds/hits, thinking truncations, recovered submissions,
input/thinking/output costs, chain counts and unresolved annotation coverage.
An incomplete schedule or partial thinking cannot support a deeper-exploration
claim by itself. Every failure stays in the denominator and raw archive.

Provider protocol reference: [DeepSeek Responses API](https://api-docs.deepseek.com/guides/responses_api/).
The destination and payload export are now explicitly approved. The initial
opaque-replay qualification returned only 1,245 input tokens: its shape pass
did not establish historical thinking consumption. The protocol was refrozen
before any solver trial to use lossless assistant-message projection and
require a substantial actual input increment in live qualification. Both
qualification costs/failures are retained separately. The original total
authorization is 73 provider calls; two qualification attempts and six rejected solver calls leave at most
65 final solver calls after six rejected solver calls. No fixture, judge or per-cell token ceiling is changed.
