#+title: 10.10 Build and Test Ownership

* Command ownership

=gerbil build= owns library compilation through the package's existing native
Make specification. =gerbil test= owns suite import, Case execution and Harness
results. Ordinary test modules declare suites and fixtures; they do not start a
second package test run. Integration tests of the compiler/process boundary may
exercise that boundary explicitly; this is not the ordinary suite dispatcher.

The retired =unit-tests.ss= dispatcher and the locally patched/rebuilt =gxtest=
are removed. No replacement test engine or Builder is introduced.

* External selection and resource policy

=init.exports.tests= publishes the official Harness input spec: a list of test
file paths, consumed by the installed =gerbil test=. It is not a package
manifest, a Make target list, or a replacement TestSuite format.
=.for-directory= projects a bounded regression directory through the same
source owner, pruning excluded branches before filesystem access. Listing
inputs does not read all suite bodies. Explicit admission binds leaf bytes and
rechecks them after execution; directory membership is guarded independently.
=just test-root= prepares shared prerequisites
once and runs the selected files serially, preserving the package's 1200-second
aggregate limit. The selected manifest must be nonempty and contain existing
=*-test.ss= files. ASP discovery and its product Profile wrapper are removed.

=dev/tests.ss= is a thin CLI consumer of =agentic-ai-lab.init.exports.tests=.
It asks the existing =.for-files= method for a bounded demand, refines that
demand's execution policy and explicitly calls =.run=. It does not construct
another =TestingScript.= or select a compiler. The same entry serves ordinary
focused tests and the existing long-budget diagnostic command. Core owns
selection, demand-scoped support preparation, native issuance and execution.
Its command remains the installed =gerbil test=, with the original pre-import
heap fence and watchdog. Core's source guard and exact
=MODULE-OK=/=HARNESS-OK=/=OK= result admission remain in force, including failure
markers even when a tool exits zero. This is outside the test Case, not a Case
launching another test Harness.

The public owner is the same init export that publishes =std-make-spec=:

#+begin_src scheme
(def tests
  (.call (.get agentic-ai-lab.init.exports tests) .for-files
    '("t/gerbil-runtime-import-test.ss")))
;; No process is started by obtaining this object.
(.call tests .run)
#+end_src

The legacy =t/= exclusions remain plain data in the CLI consumer until the
suites move to module-owned directories. They are applied by the init-owned
directory projection, not by ASP or another product scanner. The retired
=dev/test-file.ss=, =dev/test-files.ss= and =dev/testing-profiles.ss= do not
remain as forwarding entrypoints. The package-file diagnostic uses this same
publication instead of constructing a separate qualification Script.

** Syntax binding is a separate obligation

=init.exports.tests= already publishes selection, preparation and execution.
It does not yet inject the lexical =yuanxu-test-case= or Fixture macro bindings
into ordinary test sources. The existing macros expand hygienically to native
=std/test= TestCases and retain their Case policy. Automatic binding must join
the existing compiler-source role preparation on both reading and compilation;
it must preserve original locations and explicit non-default preludes. Adding
an eval-time import to a CLI, changing the global package prelude, or declaring
an alias named =yuanxu-test= would not close that obligation. No such replacement
is introduced here. Loading an init export must remain inert. A proposed
test-only package/prelude was withdrawn: neither =t/gerbil.pkg= nor a separate
testing language is required by the official Harness. Explicit native test
macro imports remain until the existing role preparation can supply them
without changing the Harness interface.

The product consumer migration is exercised through default =just test-file=:
the runtime-import control passes with an empty support spec. The build-boundary
regression passes through the init-owned demand, including inert =tests= access
and distinct cross-package entries. Its first run compiles three support units;
a second Just process reports =issuer-reused=#t=, =make-seconds=0= and
=compile-count=0=. Both complete with the required native Harness markers and
no failure markers. This demonstrates reuse of the existing issuance owner,
not a new cache or a cached test verdict. Automatic lexical macro injection and
full CI closure are not established by these runs.

Ordinary =just test-file= does not prepare Provider artifacts or Nix executables.
The full package and explicit Nix qualification prepare those inputs separately.
The Nix environment transport runs once for the full package, not on every file.
Core module-system qualifications retain their existing signed support-build
entry; this change does not replace that protocol with an unissued Make call.

** Native startup diagnosis

The unchanged five-second refusal was reproduced with failure-only Darwin stack
sampling. In that one-second sample, 56 of 95 main-thread samples were under
=___dynamic_load=/=dlopen=; 53 included dyld debugger-image notification, with
synchronous Mach-message waits visible. Only two samples were in the GC branch.
This is a sampled startup interval, not a measurement of the complete run or
proof that the host is the sole cause. It does establish that this failure
occurs while loading native images before Harness output, rather than while
compiling a test Case. The sampling time cannot earn a pass: the watchdog has
already rejected the process before collecting its stack.

The outer qualification process and the native test child must be attributed
separately. Removing the runtime import of the build entry addresses one actual
phase dependency; it does not establish that the child now meets the progress
gate. A passing build, a parsed workflow and a focused source regression must
not be reported as a passing AOT runtime or complete CI.

Before the module-publication migration, the bounded native AOT build exited zero
with no compile jobs on the hot run. The default
=just test-file t/build-projection-observability-test.ss= also exits zero with
=MODULE-OK=, =HARNESS-OK= and final =OK=, without failure markers. Workflow lint
and whitespace checks pass. These results qualify phase separation and native
Make reuse; the failed child startup, Nix build and scale results above remain
open.
